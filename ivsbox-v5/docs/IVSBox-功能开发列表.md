## 0. 先记住一句话

单片机开发是「**一个 main 大循环 + 若干中断**」；Linux 用户态开发是「**一个事件循环 + 一堆文件描述符 + 多个进程**」。

后面所有步骤的顺序，都是围绕"**先把事件循环立起来，再往里面挂功能**"排的。
顺序颠倒会返工 —— 例如先按轮询方式写完 UART 帧解析，再补事件循环，就得把解析器从"主动读"改成"回调驱动"。

所以：**S01→S02→S03 是地基，不要跳。**

## 1. 心智模型对照（单片机 → Linux 用户态）

先过一遍这张表，后面看步骤时才不会觉得"为什么这么绕"。

| 你熟悉的做法（单片机） | Linux 用户态的做法 | 本项目落位 |
|---|---|---|
| `while(1)` 里轮询各标志位 | `epoll_wait()` 阻塞等待，谁有事叫谁 | `src/app/` Reactor |
| SysTick / 定时器中断 | `timerfd_create()` + epoll —— **超时也变成一个"可读事件"** | S03 |
| 串口中断 + 环形缓冲 | `open("/dev/ttyS1", O_NONBLOCK)` + termios raw + epoll | `src/hal/` + `src/modules/link/` |
| 全局变量跨任务共享 | 单写者原则：业务状态只在 Reactor 里改；跨进程走 IPC | `ivsboxd` 是唯一权威 |
| RTOS 任务间队列 | 进程内：有界队列 + eventfd；进程间：Unix socket | S03 / S08 |
| `delay_ms(100)` 阻塞延时 | **禁止**在事件循环内延时，改成定时器事件 | 见 §7 坑 2 |
| 中断里做业务逻辑 | 回调必须短；慢活丢给 worker | S03 慢任务池 |
| 看门狗寄存器喂狗 | `/dev/watchdog`，不喂就**整机复位** | S18 |
| 上电初始化后一直跑 | 进程随时可能被杀 / 重启，必须**无状态启动** | 配置 + 状态快照 |
| Flash 读写参数 | 文件 + `fsync` + `rename` 原子替换；结构化数据用 SQLite | S02 / S13 |
| `printf` 看现象 | syslog → logd；`/proc/<pid>/*` 查运行时状态 | S02 |
| 一个工程一个 `main` | 一个仓库多个可执行文件 + 共用静态库 | CMake 已就位 |
| `malloc` 随意用 | 所有队列 / 缓冲必须有上限，长稳看 RSS 是否增长 | 全部任务 |
| 不用考虑 API 失败 | Linux API **几乎都会失败**，必须逐个判断返回值 + `errno` | 全部任务 |
| 编译一次烧一次 | 改代码 → 交叉编译 → `scp` → 重启进程看日志（**很快，别怕**） | S01 |

## 3. 分步详解

每个任务给出：目标 / 目录 / 关键 API / 要点 / 验收。
「关键 API」一栏是给你**照着查 man 手册**的，不是要背。

### 阶段一　能编译、能上板

#### S01　交叉编译与上板跑通

- **目录**：`cmake/toolchains/tina-arm.cmake`
- **关键动作**
  1. 在 Tina SDK 里 `source build/envsetup.sh && lunch`，导出 `TINA_SDK_ROOT`
  2. 确认工具链前缀（`arm-openwrt-linux-` 或 `arm-openwrt-linux-muslgnueabi-`），必要时用 `-DIVSBOX_CROSS_PREFIX=...` 覆盖
  3. `cmake -DCMAKE_TOOLCHAIN_FILE=... -DIVSBOX_BUILD_TESTS=OFF` 配置 ARM 目标
  4. `scp` 到板子，手工 `./ivsboxd` 跑一次（**先不要用 procd**）
- **验收**：板子上看到 `IVSBox 0.1.0 (ipc proto v1, cfg schema v1)`；`file ivsboxd` 显示 ARM ELF。
- **提醒**：本机没有 cmake。主机侧的等价验证用直接调 gcc（现有 `build/_verify.txt` 就是这么做的）；
  ARM 侧必须在 SDK 环境里跑 cmake。这一步搞通之前不要往下走。

#### S02　core 基础设施

- **目录**：`src/core/`、`src/hal/`
- **要做的六件小事**（每件都能独立单测）
  1. **日志**（已有 `iv_log.c`）：先够用即可，后续接 syslog
  2. **错误码**（已有 `iv_err.c`）：统一 `0 = 成功 / 负数 = 失败`
  3. **时钟**（已有 `iv_clock.c` / `iv_clock_mono_ms`）：**所有时长必须用单调时钟**
  4. **JSON**：选 cJSON（2 个文件，直接进仓库）；**包一层 `iv_json_*` 适配层**，不让 cJSON 类型扩散到业务代码（架构文档 §6 依赖规则）
  5. **CRC8 / CRC16**：自己写，20 行。这部分你单片机时代写过，直接迁移
  6. **环形缓冲**：单生产者单消费者，用于串口收数据
  7. **配置读写**：`/data/ivsbox/config/*.json`，写入必须 `tmp 文件 → fsync → rename → fsync(目录)`，否则掉电会得到半个文件
- **关键 API**：`open` / `write` / `fsync` / `rename` / `stat` / `mkdir`
- **验收**：单元测试 5 项 —— JSON 往返、CRC 已知向量、环形缓冲满/空边界、非法配置被拒绝、时钟单调性。
- **可迁移经验**：CRC、环形缓冲、状态机，这几样单片机和 Linux 完全一样。

#### S03　事件循环（Reactor）—— 本项目的心脏

- **目录**：`src/app/reactor.c`、`src/app/reactor.h`
- **关键 API**：`epoll_create1` / `epoll_ctl` / `epoll_wait`、`timerfd_create` + `timerfd_settime`、
  `signalfd`、`eventfd`、`pipe`
- **要做的事**
  1. 统一注册接口：`iv_reactor_add(fd, events, cb, ctx)` / `iv_reactor_mod(...)` / `iv_reactor_del(fd)`
  2. 定时器封装：`iv_timer_after(ms, cb, ctx)` / `iv_timer_every(ms, cb, ctx)`，底层就是 timerfd ——
     **这样"超时"和"数据到了"在代码里是同一种东西**，不用两套逻辑
  3. 信号一律走 `signalfd`，**不要**在 `signal()` 的处理函数里写业务
  4. 每轮循环 `g_loop_progress++`（原子变量），后面 S18 健康线程靠它判断"主循环还活着吗"
  5. 慢任务：另开一个 `eventfd` 回传结果（S03 先留接口，S10 之后才用得上）
- **要点**
  - **回调必须短**：任何可能阻塞的操作（DNS、SQLite、文件、网络超时）都不能放这里
  - 用**水平触发**（默认）就够了，别一上来用边缘触发，`O_NONBLOCK` 配不好会死循环
- **验收**：单测覆盖"定时器到期回调""eventfd 唤醒""signalfd 触发"；`strace -e epoll_wait,read,write ./ivsboxd` 观察循环。
- **提醒**：这是**第一个和你过去完全不同的东西**。建议单独写一个小 demo（定时器 + 串口 + 信号三件事）跑通再进下一步，别急着上业务。

### 阶段二　能跟采集板说话

#### S04　串口 HAL

- **目录**：`src/hal/iv_serial.c`、`include/ivsbox/iv_serial.h`
- **关键 API**：`open` / `tcgetattr` / `cfmakeraw` / `cfsetispeed` / `tcsetattr`（配 `VMIN=0`、`VTIME=0`）、`O_NONBLOCK`
- **要点**
  - **raw 模式**：关掉 ICANON / ECHO / 流控，否则收到的数据会被内核加工过，帧就对不上了
  - 波特率确认：460800 要确认 T113 的 UART 时钟分频真能出这个速率（分频后误差 < 2%）
  - **一次 `read` 只保证"至少读到 1 字节"**，绝不能假设读到一整帧（这是从单片机转过来最容易错的一点）
  - 打开失败要能重试：板子刚上电时采集板可能还没就绪
  - `read` 返回 `-1` 且 `errno == EINTR` 是正常现象，要重试而不是当错误
- **验收**：用 `socat -d -d pty,raw,echo=0 pty,raw,echo=0` 造一对虚拟串口，一端跑程序、另一端灌数据，验证收发。

#### S05　板间协议模拟器（**先做模拟器，再做协议**）

- **目录**：`tools/uart_simulator/`
- **为什么必须先做**：没有它，你只能等采集板固件同步改好才能测；有了它，两边**并行开发**，而且你能随时复现半包/粘包/噪声这类现场偶发问题。
- **要做的事**：PC 端程序，接虚拟串口（或 TCP 转串口），按**现网既有帧格式**收发；能按脚本制造异常。
- **验收**：能自动跑五种场景 —— 正常应答 / 应答超时 / CRC 错 / 半包 / 粘包。
- **定位**：架构文档 §17 里 M0/M2 的**硬前置**，优先级等同于业务代码。

#### S06　板间链路（modules/link）

- **目录**：`src/modules/link/`
- **核心是一个字节流解析状态机**：找帧头 → 收长度 → 收载荷 → 校验 → 吐出一个完整帧
  - 必须支持：**半包**（攒着等）、**粘包**（循环解析）、**噪声**（逐字节滑动重同步）、
    **长度上限**（防越界）、**帧超时**（半帧丢弃）
  - 这部分和你单片机里写的 UART 收包状态机**是同一类东西**，经验可直接迁移
  - 与业务解耦：解析器只负责吐"完整帧"，不判断业务含义
- **状态镜像**：把采集板上报的计量 / 温湿度 / 门磁等存成一张"影子表"，T113 侧以此为准
  （因为 T113 自己读不到那些传感器）
- **兼容纪律（架构文档 §1.3）**：第一版**严格按现网既有帧实现，不加字段、不改 CRC、不动字节序**。
  可靠层增强（seq/ACK）要等和采集板约定协议版本之后再做。
- **验收**：用 S05 的模拟器跑输入边界用例；**这一项必须做 fuzz 测试**（乱字节灌进去不能崩、不能死循环）。

#### S07　GPS

- **目录**：`src/modules/gps/`
- **要点**：GPS 就是一个串口 + NMEA 文本解析，**直接复用 S04 的串口 HAL**
  - 波特率通常 9600，先确认板子上 GPS 挂在哪个 `/dev/ttyS*`
  - 优先用镜像里现成的 `gpsd`（先查 `which gpsd`）；没有就自己写最小 NMEA 解析（`$GNRMC` / `$GNGGA`）
  - 首次有效定位立即上报，之后按位移阈值或最长周期上报
  - 定位无效时保留最近有效坐标 + 附无效标志
- **验收**：`cat /dev/ttyS2` 能看到 NMEA 语句；程序能解析出经纬度并打日志。

### 阶段三　进程间通信

#### S08　IPC 骨架

- **目录**：`src/core/iv_ipc_codec.c`（编解码，可在主机单测）+ `src/hal/iv_uds.c`（socket 机械部分）
  —— 这个拆分是刻意的：**协议编解码留在 core，系统调用留给 hal**，符合 §6 依赖规则。
- **关键 API**：`socket(AF_UNIX, SOCK_SEQPACKET, 0)`、`bind`、`listen`、`accept4`、
  `send`/`recv`、`getsockopt(SO_PEERCRED)`、`chmod(sock_path, 0660)`
- **要点**
  - 选 SEQPACKET 是因为**传输层保留消息边界** —— 你不用自己找包尾，省掉一整类 bug
  - 单包大小有上限（`IVS_IPC_MAX_PAYLOAD` = 64KB），超限的数据走文件句柄传递或分片
  - `SO_PEERCRED` 校验对端 uid / gid，只允许自己的三个进程连
  - 客户端要能"**服务端还没起来就重试**"，指数退避。这条不做，冷启动会打摆子（缺口 G5 的进程侧一半）
  - 长任务模式：立刻返回 `task_id`，结果通过事件通知 —— 不要让调用方干等
  - **头文件布局已被 `_Static_assert` 钉死**（`sizeof` = 32 而非 28，offset 12 有对齐空洞）：
    所以**不能把结构体整体 memcpy 到 socket**，必须按字段显式序列化
- **验收**：写 `tests/integration/ipc_echo`，服务端 echo，客户端发 1000 条不同长度的包，验证边界不串、不粘。

### 阶段四　能跟平台说话

#### S09　平台协议模拟器

- **目录**：`tools/platform_simulator/`
- **要能模拟**：平台下发命令、应答、心跳超时、断开重连、补传接收。
- **为什么同样先做**：平台侧改动比采集板更慢，没有模拟器你会被卡死。

#### S10　平台协议（modules/proto）

- **目录**：`src/modules/proto/`
- **要点**
  - **表驱动命令路由**：每条命令声明"本地执行 / 转发采集板 / 本地并转发"，**未知命令是否转发由白名单决定，不能无条件透传**
  - 所有请求带关联号 + 超时 + 幂等或去重规则
  - 发送队列分级：**门禁/控制 > 告警 > 状态 > 媒体**，并设字节与条目上限
  - 断线数据入**有容量上限的持久队列**，恢复后按序补传（第一版可以先只做内存队列）
  - 平台侧私有协议**字节级兼容现网**，服务端无感知（架构文档 §1.3）
- **验收**：用 S09 模拟器跑通"上线 → 收命令 → 执行 → 上报 → 断线 → 重连 → 补传"全流程。

### 阶段五　网络与探活

#### S11　rtnetlink + 统一探活引擎

- **目录**：`src/hal/iv_netlink.c`、`src/modules/probe/`
- **关键 API**：`socket(AF_NETLINK, SOCK_RAW, NETLINK_ROUTE)`、`RTM_GETLINK` / `RTM_GETADDR` /
  `RTM_GETROUTE`、`RTMGRP_LINK` / `RTMGRP_IPV4_IFADDR`（订阅变化）
- **要点**
  - **禁止解析 `ifconfig` 文本**（架构文档 §14 明确要求）—— 文本格式会变、编码会乱、还慢
  - 探活三种模式：ICMP（原始套接字，需 `CAP_NET_RAW`）/ 非阻塞 TCP `connect` / RTSP `DESCRIBE`
  - 统一统计口径：滑动窗口 + EWMA + 滞回（连续失败 `fail_n` 次才判失败、连续成功 `ok_n` 次才判恢复）+ 失败细分码
  - 这一处实现，**四处复用**：主网检测、摄像机巡检、双 WAN 切换、平台保活
- **验收**：拔网线 / 拔 4G 天线 / 把交换机断电，观察状态判定与恢复是否符合预期；ICMP 被禁时 TCP 成功仍判可用。

#### S12　双 WAN 状态机 + 持久队列

- **目录**：`src/modules/netmgr/`
- **要点**
  - 默认无线优先，无线失败切有线，无线稳定 `hold_s` 后回切
  - **切换事务必须包含"关闭绑定旧接口的 TCP 连接并从新出口重建"** ——
    普通 TCP 不能跨接口迁移，这是 v4 曾经的错误认识，v5 已修正（架构文档 §7.2）
  - 出口绑定用 `SO_BINDTODEVICE`，路由用策略路由（`ip rule` + 独立路由表，经 netlink 配置）
  - 断网期间数据进本地队列，恢复后按优先级补传
  - 媒体（大流量）在稳定期结束前不恢复上传，避免抢占控制链路
- **验收**：架构文档 §16.2 的验收场景 1 和 2。

### 阶段六　配置与设备管理

#### S13　配置事务 + 状态快照

- **目录**：`src/modules/config/`
- **要点**：schema 校验 → 临时文件 → `fsync` → `rename` → `fsync` 目录；
  更新前做类型/范围/引用/跨字段校验；**应用失败时保留旧配置继续运行**；变更以事务方式通知相关模块，**不允许部分生效**。
- **验收**：写入过程中断电（或 `kill -9`）不产生半截文件；非法配置被拒绝且进程继续正常跑。

#### S14　设备发现与档案（ONVIF + SNMP）

- **目录**：`src/modules/device/`、`src/modules/snmp/`
- **要点**
  - ONVIF WS-Discovery 多播发现 → `GetDeviceInformation` / `GetNetworkInterfaces` / `GetOSDs` 补档案
  - SNMP 优先用成熟库（net-snmp 裁剪）而不是自己写 BER 编解码
  - OID **模板化**：按品牌/型号匹配模板，未命中回落 generic（只采 MIB-II）
  - 设备主键用 MAC（稳定），**IP 作为可变属性**
  - **这两件事是"慢任务"，必须跑在 worker 里**，绝不能占事件循环
  - 摄像机口令只存密钥引用，不进普通档案导出内容
- **验收**：对手头真实设备（海康 / 大华）跑出品牌、型号、序列号、MAC、OSD。

#### S15　门锁门磁 + 自愈策略

- **目录**：`src/modules/access/`、`src/modules/recovery/`
- **要点**
  - 开锁请求带**事务号**（防重传造成重复动作），需要来源鉴权 + 有效期 + 去重 + 审计
  - 门开事件**立即上报，不等抓图结果**；抓图作为异步联动
  - 自愈四道防线缺一不可：**冷却**（不反复）、**频率上限**（不风暴）、
    **上游关联**（一片设备同时掉线先查交换机，不逐个重启）、**熔断**（超限只告警等人工）
  - 所有时长与窗口用**单调时钟**，不要用墙钟（缺口 G9）
- **验收**：模拟摄像机连续失败，验证"多层确认后才动作 → 达上限熔断 → 只告警"。

---

### 阶段七　媒体与 Web

#### S16　ivsbox-media（独立进程）

- **目录**：`media/`
- **建议顺序**：**抓图 → 录像 → 音频**（从简单到复杂，且抓图能立刻验证链路）
  - 抓图：优先用摄像机 HTTP 抓拍接口，不行再从 RTSP 取关键帧
  - 录像：**码流直封装，不在 T113 上转码**；按 1~5 分钟切片，临时文件关闭成功后原子改名
  - 音频：先跑通 ALSA 放一个 WAV；编解码与优先级抢占后面再说
- **要点**
  - 每路 RTSP 会话都要有建连 / 无数据 / 读写 / 停止超时，否则一个卡住的会话会拖死整条流水线
  - 同时录像路数、总码率、写盘带宽都要设上限（数值见缺口 G1，**先写 TODO 常量，别拍脑袋**）
  - 存储水位：85% 清最旧 → 90% 限新任务 → 95% 停录像告警 → 70% 恢复
  - 崩溃只影响媒体，主控不受影响 —— 这就是独立进程的价值

#### S17　ivsbox-web（独立进程）

- **目录**：`web/`
- **要点**
  - **不要自己写 HTTP 解析器**，用 uhttpd 或成熟嵌入式 HTTP 库，选定一种固化版本
  - 所有数据经 IPC 问主控，**不直接读数据库、不直接读媒体目录**（架构文档 §10.1）
  - 摄像机 Web 反向代理只允许访问档案内的 IP 与允许端口，**禁止客户端传任意地址**（否则成为 SSRF 跳板）
  - 高风险操作（开锁 / 重启 / 升级 / 代理授权）要二次确认 + 审计
  - 权限：以无特权用户运行

### 阶段八　看护、升级、交付

#### S18　健康门控 + 看门狗

- **目录**：`src/app/`、`src/hal/iv_watchdog.c`
- **关键 API**：`open("/dev/watchdog")`、`write` 喂狗、`ioctl(WDIOC_SETTIMEOUT)`
- **要点（这里是"设备无故重启"的根因区）**
  - 健康判据**只看主事件循环的原子进度号 + 关键链路时间戳**
  - **慢任务超时不得参与喂狗** —— 4G 弱网下 SNMP 超时是正常的，把它算进健康判据会导致整机复位（缺口 G2）
  - 时间关系：`watchdog timeout > procd 重启间隔 + 进程启动到首次喂狗的时间`
  - 停止喂狗前，最小故障信息必须先 `fsync` 落盘，否则复位即丢证据
- **验收**：人为让 SNMP 指向黑洞地址（30s 超时），设备**不复位**且产生告警；
  人为卡死主循环，设备**复位**且能在日志里看到复位原因。

#### S19　OTA（ivsboxd 协调 + ivsbox-updater 执行）

- **目录**：`src/modules/ota/`、`updater/`
- **要点**
  - **强制数字签名**，CRC / 哈希不能替代发布者认证
  - 应用级双版本：`/opt/ivsbox/releases/<ver>` + `current` / `previous` 符号链接原子切换
  - 确认窗口内健康检查不通过就回滚
  - **不要**拿 U-Boot 的 rootfs 槽位冒充应用回滚（架构文档 §11.2 与 §11.3 是两条独立路径）
- **验收**：故意放一个坏版本，验证自动回滚；放一个签名错误的包，验证被拒绝。

#### S20　打包、出厂、长稳

- **目录**：`packaging/`、`scripts/`
- **要点**：ipk 的 postinst 要建用户、建目录、设权限（见 `packaging/README.md`）；
  量产后关闭 `ivsbox-provision` 入口；跑 **72 小时长稳**，盯 RSS 与 fd 是否增长。
- **验收**：架构文档 §16.2 的 10 条验收场景逐条通过。

## 5. 第一版（v1）的最小闭环

**建议 v1 只做到 S10。** 理由：只有当"板间通了 + 平台通了 + 日志能查"这三件事同时成立，
你才有一个**能自己验证自己**的系统。

### v1 完成的定义

```text
ivsboxd 启动
  → 打开串口，与 uart_simulator 收发板间帧（含半包/粘包/CRC 错恢复）
  → 通过 IPC 接受一个客户端连接（ipc_echo 测试客户端）
  → 连接 platform_simulator，完成上线、收命令、执行、上报、断线重连
  → 全程日志可查，进程连续运行 24h 不重启、RSS 不增长
```

**v1 明确不做**：Web、媒体、音频、ONVIF/SNMP、自愈、自愈策略、OTA、隧道、双 WAN。
这些都建立在 v1 的地基上，地基不稳就往上堆，后面全部要返工。

## 6. Linux 用户态工程纪律（每条都要遵守）

1. **所有系统调用都判断返回值**；`errno` 要打进日志。Linux API 失败是常态，不是异常。
2. **事件循环回调内不得阻塞** —— 不 DNS、不 SQLite、不等网络、不做长文件 IO。
3. **所有队列、缓冲、连接数必须有上限**，满时明确返回"忙"，不无限排队。
4. **时长/超时/窗口一律用 `CLOCK_MONOTONIC`**，墙钟只用于展示与证书校验。
5. **写文件必须 `fsync` + `rename`**，否则掉电得到半截文件。
6. **信号只用于唤醒，不写业务**（用 `signalfd`）；启动时 `signal(SIGPIPE, SIG_IGN)`。
7. 打开 fd 用完即关；长时间运行要能回答"现在开了多少个 fd"。
8. **日志文本一律 ASCII**，中文只写在注释里（板端控制台 GBK，中文日志抓下来是乱码）。
9. 每写完一个模块，**先写单测再联调**；主机上能跑的单测不要等到板上跑。
10. 改动前先 `git commit`；板上调试靠"改代码 → 编译 → scp → 重启进程看日志"，这个循环很快。

## 7. 单片机工程师最容易踩的 14 个坑

| # | 坑 | 后果 | 正确做法 |
|---:|---|---|---|
| 1 | 在事件循环回调里做阻塞操作 | 整个进程卡死，所有功能一起停 | 丢给 worker（S03 慢任务池） |
| 2 | 用 `sleep()` / `usleep()` 做延时 | 卡住整个事件循环 | 用 timerfd 定时器事件 |
| 3 | 假设 `read()` 一次读到一整帧 | 偶发解析错乱，现场难复现 | 自己攒缓冲，按状态机解析（S06） |
| 4 | 不处理 `EINTR` | 信号一到就报错退出 | `EINTR` 时重试 |
| 5 | 忘了 `O_NONBLOCK` | epoll 水平触发下死循环占满 CPU | 所有非阻塞 fd 必须加 |
| 6 | 用 `gettimeofday` 算时长 | 对时后时长变负 / 巨大 | 用 `CLOCK_MONOTONIC` |
| 7 | 直接 `memcpy` 结构体到 socket | 因对齐空洞导致对端解析错位 | 按字段显式序列化（`iv_ipc.h` 已注明） |
| 8 | 忘了关 fd / 忘记释放内存 | 长稳 72h 后资源耗尽 | 长稳测试盯 `/proc/<pid>/fd` 与 `VmRSS` |
| 9 | 在信号处理函数里调 `printf` | 死锁（`printf` 非异步信号安全） | 用 `signalfd` |
| 10 | 打开 `/dev/watchdog` 后忘了喂 | 整机复位 | S18 门控喂狗 |
| 11 | 线程栈用默认 8MB | 128MB 内存的板子上开几个线程就 OOM | 显式 `pthread_attr_setstacksize` |
| 12 | `printf("%d", uint64)` | 64 位值被截断 | 用 `PRIu64` |
| 13 | 认为"写文件是原子的" | 掉电后配置/索引损坏 | `tmp → fsync → rename` |
| 14 | 没考虑进程被重启 | 重启后状态全丢，现场表现"设备失忆" | 无状态启动 + 状态快照（S13） |

## 8. 与缺口清单（G1~G19）的关系

按你的要求，**第一版不处理风险项**。但有几处会顺手撞上，处理原则如下：

| 缺口 | 撞上的时机 | v1 的处理原则 |
|---|---|---|
| G1 资源预算 | S16 媒体、S17 Web | **所有上限先写 TODO 常量+注释**，不拍数字；数值待 M0 实测回填 |
| G2 喂狗判据 | S18 | S18 本来就按"只看主循环进度"实现，等于顺手解决 |
| G3 提权机制 | S19 OTA | 不在 v1 范围 |
| G4 媒体文件路径 | S16/S17 | 不在 v1 范围；届时三选一（推荐 `SCM_RIGHTS` 传 fd） |
| G5 启动分级 | S08 + 三个 procd 脚本 | **S08 客户端重连退避必须做**（这是进程侧的一半），就绪分级可后补 |
| G6 慢任务池容量 | S03/S10 | S03 先把队列满"丢最旧 + 计数"做对，容量参数后调 |
| G7 模块边界强制 | 每个阶段 | 目录已按边界建好，**写代码时自觉不跨模块访问私有头**；检查脚本后补 |
| G8 respawn 熔断 | S18 | procd 脚本里已有基础阈值，告警与 failsafe 后补 |
| G9 时钟纪律 | S11/S13/S15 | S02 已定"时长用单调时钟"，**照做即可，等于顺手解决** |
| G10~G19 | 各自阶段 | 按缺口清单的关闭顺序，v1 之后统一处理 |
