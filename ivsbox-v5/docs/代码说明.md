## 2026-09-23 16:15　交叉编译工具链文件对齐实测环境

- **涉及文件**：`ivsbox-v5/cmake/toolchains/tina-arm.cmake`（修改）
- **干了什么事**：只改这一个文件，三处改动。

  1. **工具链前缀默认值**：`arm-openwrt-linux-` → `arm-linux-gnueabi-`
     （`IVSBOX_CROSS_PREFIX` 缓存变量保留，仍可用 `-DIVSBOX_CROSS_PREFIX=...` 覆盖）
  2. **新增 `IVSBOX_SYSROOT` 缓存变量**，默认 `/opt/EmbedSky/Tina/arm-buildroot-linux-gnueabi/sysroot`
  3. **sysroot 解析改为三级，不再致命**：
     - ① `IVSBOX_SYSROOT` 指向的目录存在 → 用它
     - ② 否则若已导出 `TINA_SDK_ROOT` → 用 `$TINA_SDK_ROOT/out/t113/staging_dir/target`
     - ③ 都不可用 → 只 `WARNING` 并退回工具链自带 sysroot，配置继续
     - 删除原来"未设置 `TINA_SDK_ROOT` 就 `FATAL_ERROR`"的分支
     - 命中 sysroot 时同时设置 `CMAKE_SYSROOT` 与 `CMAKE_FIND_ROOT_PATH`，
       并删掉文件下方重复设置 `CMAKE_FIND_ROOT_PATH` 的那一行

  数据流很简单：这个文件只决定两件事——**用哪个前缀去调 gcc**、**头文件和库去哪个 sysroot 找**。
  其余（`-Werror` 等编译选项、Release 优化参数、板端关闭测试）未动。

- **解决什么问题**：
  - **改动前**：脚本按"全志原厂 OpenWrt SDK"的假设写死了两处平台事实——前缀 `arm-openwrt-linux-`、
    sysroot 为 `${TINA_SDK_ROOT}/out/t113/staging_dir/target`，且未导出 `TINA_SDK_ROOT` 时直接中断配置。
  - **实际环境**（2026-09-23 在天嵌 TQT113 编译 VM 上实测）与该假设不符：

    | 项 | 实测值 |
    |---|---|
    | 工具链前缀 | `arm-linux-gnueabi-` |
    | 编译器 | gcc 7.3.1（Linaro 7.3-2018.05），`--with-float=soft --with-arch=armv7-a --with-tune=cortex-a9` |
    | 安装位置 | `/opt/EmbedSky/Tina/`（`bin/` 下是转发脚本，实体在 `opt/ext-toolchain/bin/`） |
    | sysroot | `/opt/EmbedSky/Tina/arm-buildroot-linux-gnueabi/sysroot`（glibc 2.25） |
    | Tina SDK | **不存在**，没有 `staging_dir` |

  - 结论：照原脚本执行必然配置失败（前缀找不到编译器 + `TINA_SDK_ROOT` 致命检查）。
  - **改动后**：默认参数即匹配当前实测环境，配置命令无需附加 `-D` 参数；
    同时保留原厂 Tina SDK 路线（导出 `TINA_SDK_ROOT`，或 `-DIVSBOX_SYSROOT=` 显式指定）。

- **为什么这么做**：
  - 选"改默认值 + 保留覆盖入口"，而不是"让使用者每次手敲一长串 `-D`"：
    当前只有一台实测可用的编译机，默认值贴合现实，出错面最小。
  - 把 `TINA_SDK_ROOT` 从致命检查降级为候选路径，而不是删除该分支：
    后续若换用全志原厂 SDK，仍可零改动复用同一份工具链文件。
  - 不追加 `-mfloat-abi=soft`：该工具链 configure 阶段已 `--with-float=soft`，
    实测不指定也能编出正确的软浮点目标，加了反而是在重复约束。
  - 被否掉的方案：把 sysroot 路径写死到 `CMAKE_FIND_ROOT_PATH` 而不设 `CMAKE_SYSROOT`——
    实测该工具链 `-print-sysroot` 的结果就是同一目录，显式设置 `CMAKE_SYSROOT` 让语义更清楚，故采用。

- **影响范围**：**只影响板端（ARM）构建**，即 `-DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/tina-arm.cmake`。
  主机侧 `build/host` 不使用该工具链文件，单测与 fuzz 不受影响。
  默认值变更后，在其他环境（原厂 Tina SDK / musl）上构建必须先显式 `-DIVSBOX_CROSS_PREFIX=...`。
  未改动：`CMAKE_C_FLAGS_RELEASE`（`-O2 -g -ffunction-sections -fdata-sections`）、
  `CMAKE_EXE_LINKER_FLAGS_RELEASE`（`-Wl,--gc-sections`）、`IVSBOX_BUILD_TESTS OFF`。

- **未覆盖 / 风险**：
  - 架构与浮点 ABI 是否与板端 rootfs 完全一致，**尚未在真实板子上验证**。
  - sysroot 内 glibc 为 **2.25**，与天嵌《应用开发手册》中"需要 glibc 2.34"的说法不一致；
    以实测为准，但板端 rootfs 的 libc 版本**仍需上板比对**。
  - 工具链是 buildroot + glibc，而非项目文档假设的 OpenWrt + musl；
    这对 S02（logd）、S17（uhttpd）、S18（procd respawn）、S20（ipk 打包）的技术选型有影响，
    须待 `scripts/bsp-survey.sh` 在板端实测定性，**当前只登记为待确认，不下结论**。
  - cmake 尚未在该 VM 安装，因此"经 cmake 实际跑通"这一步**尚未验证**。

- **验证方式与结果**：在 `tqt113`（192.168.2.115，Ubuntu 22.04.2 x86_64，用户 embedsky）上执行：

  ```sh
  TOOL=/opt/EmbedSky/Tina/bin/arm-linux-gnueabi-
  SYSROOT=/opt/EmbedSky/Tina/arm-buildroot-linux-gnueabi/sysroot

  # 1) 工具链自身默认 sysroot（用于核对脚本默认值）
  ${TOOL}gcc -print-sysroot
  # -> /opt/EmbedSky/Tina/arm-buildroot-linux-gnueabi/sysroot

  ${TOOL}gcc -print-file-name=libc.so.6
  # -> /opt/EmbedSky/Tina/arm-buildroot-linux-gnueabi/sysroot/lib/libc.so.6

  # 2) 用该前缀 + sysroot 编译最小程序
  #    结果：compile_exit=0
  ${TOOL}gcc --sysroot=$SYSROOT -O2 -Wall -o /tmp/ivs_probe /tmp/ivs_probe.c

  # 3) 检查产物 ABI
  file /tmp/ivs_probe
  # -> ELF 32-bit LSB executable, ARM, EABI5 version 1 (SYSV), dynamically linked,
  #    interpreter /lib/ld-linux.so.3, for GNU/Linux 3.2.0

  ${TOOL}readelf -l /tmp/ivs_probe | grep -A1 INTERP
  # -> [Requesting program interpreter: /lib/ld-linux.so.3]
  ```

  **结论**：

  1. 前缀 `arm-linux-gnueabi-` 可用，产物为 ARM EABI5 32 位 ELF。
  2. 脚本默认 sysroot 与工具链 `-print-sysroot` 输出**完全一致**，默认值正确。
  3. 产物解释器为 `/lib/ld-linux.so.3`，由 sysroot 中的 `ld-2.25.so` 提供 →
     **板端 rootfs 必须存在 `/lib/ld-linux.so.3` 且 libc 与 2.25 兼容**；
     这是 S01 上板的第一项检查，若有偏差此即根因。
  4. 临时文件（VM 侧 `/tmp/ivs_probe*`、`/tmp/ivsbox-verify`）已删除。

  **尚未验证**：`cmake -S . -B build/arm -DCMAKE_TOOLCHAIN_FILE=...` 的完整配置与 `ivsboxd` 编译，
  以及上板运行。前置条件是：VM 安装 cmake、源码进入 VM（计划走 git clone）。
