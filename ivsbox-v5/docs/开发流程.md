> 唯一依据：根目录《T113运维终端-系统架构设计.md》（下称"架构文档"），按其 §17 路线图 M1~M8 推进。

## 0. 通用规则（贯穿所有阶段）

- **开发闭环**：编译 VM（192.168.2.115）交叉编译（`arm-linux-gnueabi-` + `_GNU_SOURCE`）→ scp 上板（192.168.2.105 `/tmp`）→ COM4 串口验证。**具体命令、判读标准与故障速查见 `docs/操作手册/日常开发闭环流程.md`，此处只留链路，不重复维护。**
- **代码约束**：C11；配置与协议解析用直接字符串方式（key=value），不引入 JSON 库；`core` 不依赖 HAL，能在 Host 跑单测；模块间禁止修改对方私有数据。
- **选型纪律**：优先现成 Linux 库 → 没有再自研 → 自研时登记"待安装库清单"，做镜像时替换。
- **收尾四件事**（每个阶段结束）：更新本文档 **§0.1 实现记录**表 → 登记 `docs/修改记录.md` → git 提交推送（`github.com/ppp1234lll/T113_S4`）→ 清理临时文件。工具层规则见根目录 `AGENTS.md`。

### M1.2 Reactor 实现步骤

1. **事件基类**
   - `iv_event_t`：fd、事件回调、用户数据、所属 reactor、active/oneshot/pending 标记。
   - `iv_reactor_t`：epoll fd、事件数组、当前时间、运行标志。

2. **基础接口**
   - `iv_reactor_create()` / `iv_reactor_destroy()`。
   - `iv_reactor_add(reactor, fd, events, cb, arg)`：注册到 epoll。
   - `iv_reactor_mod()` / `iv_reactor_del()`：修改/删除事件。
   - `iv_reactor_run()`：主循环。

3. **定时器**
   - 最小堆或有序链表管理 `iv_timer_t`。
   - `timerfd` 作为 reactor 的一个 fd；到期时统一触发过期回调。
   - 接口：`iv_timer_add(reactor, timeout_ms, cb, arg)` / `iv_timer_cancel()`。

4. **信号处理**
   - `signalfd` 纳入 reactor，屏蔽 SIGTERM/SIGINT/SIGPIPE 等，由 reactor 回调处理。

5. **单次回调约束**
   - 只做解析、状态更新、分发；禁止 DNS、同步 SNMP、同步 ONVIF、长时间文件 IO、阻塞系统调用。

6. **单测**
   - Host 上模拟多个 fd、timer、signal，验证触发顺序、删除安全、重复 add 报错。

## M2 核心链路（UART + 平台 + GPS）

| # | 做什么 | 要点 |
|---|---|---|
| 1 | hal/serial | termios raw、显式关流控、设 VMIN/VTIME，纳入 Reactor；**加进程单实例锁（`flock`）**，防止两个 `ivsboxd` 抢串口 |
| 2 | UART 帧解析器 | 半包/粘包/噪声重同步/长度上限/校验失败/帧超时，单测全覆盖 |
| 3 | UART 可靠层 | 严格兼容现有协议不改帧；有 ACK 就做超时重传+去重，没有就命令级确认+状态回读 |
| 4 | 平台协议 | 表驱动命令路由（本地/转发采集板/本地并转发）；发送队列分级：控制>告警>状态>媒体 |
| 5 | GPS 与时间 | 优先 gpsd，缺失则最小 NMEA；首次有效定位立即上报；时间源优先级可配 |
| 6 | 状态镜像 | 链路恢复后全量同步，重建采集板状态镜像 |
| 7 | 模拟器 | `uart_simulator`、`platform_simulator`，供单测与故障注入 |

**退出条件**：丢包、半包、重连、重同步测试通过。

## M3 网络管理

| # | 做什么 | 要点 |
|---|---|---|
| 1 | rtnetlink 监听 | carrier/address/route；禁止轮询解析 ifconfig |
| 2 | 统一探活引擎 | 链路/ICMP/TCP/应用层四层；统一输出 RTT、丢包、连续成败；ICMP 被禁时上层成功仍判可用 |
| 3 | 双 WAN 状态机 | 无线优先→连续失败切有线→稳定回切；切换执行架构文档 §7.2 七步事务，旧接口 TCP 必须关闭重建 |
| 4 | 持久上报队列 | 断线缓存有容量上限，恢复后按序补传，不重不丢 |

**退出条件**：拔线、弱网、回切、补传验收通过（§16.2 场景 1/2）。

## M6 媒体与音频

| # | 做什么 | 要点 |
|---|---|---|
| 1 | ivsbox-media 骨架 | IPC 服务 + 有界任务队列；崩溃只重启自身，不影响 ivsboxd |
| 2 | 抓图 | HTTP 抓拍优先，退 RTSP 关键帧；串行/低并发；fsync+rename 原子落盘→索引→完成事件 |
| 3 | 断网录像 | 主网+平台双确认后启动、恢复延迟停止；码流直封装不转码；1~5 分钟切片原子改名 |

| 6 | 音频广播 | `audio_sink` 统一接口 + 优先级抢占；**§18.6 音频硬件与广播需求确认后才做** |

## M7 OTA 与加固

| # | 做什么 | 要点 |
|---|---|---|
| 1 | 升级包与验签 | 型号/版本/清单/SHA-256/数字签名；内置只读公钥，验签强制 |
| 2 | ivsbox-updater | 下载验签→装到 releases/<新版本>→current 原子切换→写 pending→重启业务 |
| 3 | 回滚 | 健康检查不过/超时/连续启动失败→启动包装恢复 previous；不用 U-Boot 槽位冒充应用回滚 |
| 4 | 故障注入 | 掉电、进程卡死、弱网、SD 满/拔卡、恶意升级包 |
| 5 | 长稳测试 | ≥72 小时，多轮网络切换与媒体启停，内存/句柄无增长 |

**退出条件**：断电回滚正确 + 长稳通过（§16.2 场景 7/8/9）。
