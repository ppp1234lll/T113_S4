============================================================
docs  ——  工程文档落点（规则 1 / 2 / 4 的权威文档目录）
============================================================

【目录作用】
  本目录是工程开发文档的唯一落点，承载仓库根 AGENTS.md 规则 1（功能回写）、规则 2
  （修改记录）、规则 4（代码说明）要求的权威文档；另含分任务操作手册子目录。
  所有 AI 助手一律使用本目录文件，不得各自维护平行副本（规则 7 文档唯一性）。

【文件说明】
  功能开发计划.md    M1~M8 全阶段计划：每步"实现什么/怎么实现/怎么验证"三要素 + §0.1 实现状态总表
  修改记录.md        规则 2 的**唯一权威修改记录**（即 xiugaijilu.md）：**倒序追加**，记修改文件、
                     问题/目的、时间；只追加，不改写、不删除历史条目
  代码说明.md        规则 4 的**权威代码说明**：只要有代码产出就追加一节，写明"干了什么事、
                     解决什么问题、影响范围、验证方式与结果"
  操作手册/          分任务详细操作手册子目录（见 操作手册/readme.txt）

【约定与注意事项】
  - 维护顺序（每步收尾四件事）：功能计划 §0.1 追加一行 → 登记 修改记录.md → git 提交推送 → 清理临时文件。
  - 修改记录.md 为**倒序**：新条目插在格式模板之后最上方；一律追加，绝不覆盖或改写历史条目。
  - 时间格式统一 YYYY-MM-DD HH:mm，必须是本机当前时间，不得填预计/占位时间。
  - 纯文档修改不必写代码说明（规则 4 第 4 条），但仍须按规则 2 登记。
  - 新建文档须先征得用户同意（规则 7 第 2 条），不得直接创建平行副本。
  - 写入前先读取目标文件最新内容再增量修改，防止覆盖另一方刚写入的记录（规则 7 第 4 条）。
