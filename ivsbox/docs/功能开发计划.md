> 唯一依据：根目录《T113运维终端-系统架构设计.md》（下称"架构文档"），按其 §17 路线图 M1~M8 推进（M0 已取消）。

## 0. 通用规则（贯穿所有阶段）

- **开发闭环**：编译 VM（192.168.2.115，用户 `user`）交叉编译（`arm-linux-gnueabi-` + `-D_GNU_SOURCE`）→ `pscp` 上板（192.168.2.105 `/tmp`）→ `plink` 执行 + COM4 串口观察。
- **代码约束**：C11；`core` 不依赖 HAL，能在 Host 跑单测；模块间禁止修改对方私有数据；依赖方向 `libivcore`(仅 libc) → `libivhal` → `libivmodules` → `ivsboxd`，靠链接顺序写死。
- **构建口径**：**只用 GNU Make**（架构文档 §15）。顶层 `Makefile` 唯一入口 + `mk/` include 片段；裸 `make` ＝ Host Debug，`make arm` ＝ 板端产物；`make test` / `make asan` 驱动测试。
- **选型纪律**：优先现成 Linux 库 → 没有再自研 → 自研时登记"待安装库清单"，做镜像时替换。
- **每步收尾四件事**：本文档 §0.1 追加一行 → 登记 `docs/修改记录.md` → git 提交推送 → 清理临时文件。工具层规则见根目录 `AGENTS.md`。
- **接口冻结依赖**（架构 §18 共 9 项）：相关步骤标注了前置项；未冻结前该步只做到"模拟器可验证"层级，不对真实对端联调。
- **载荷/配置格式口径**：按架构文档现行口径用 JSON（§5.1/§10.2）；解析库选型在 M1-S7 一并定（候选 cJSON 单文件库）。若镜像最终不放 JSON 库，届时先改架构文档再改代码，两处不脱节。

## M1 基础骨架

目标：纯 Make 构建双端可用；`ivsboxd` 骨架在板上可运行、被 procd 守护、被看门狗门控；IPC 通道可收发。**全部从零新建。**

### S1 目录骨架 + Makefile 构建体系

- **实现什么**：工程目录骨架与纯 GNU Make 构建体系（架构 §15.1/§15.2）。
- **怎么实现**：
  1. 建目录：`mk/`、`include/ivsbox/`、`src/{app,core,hal,modules/<12个子目录>}`、`tests/{unit,fuzz,integration}/`、`tools/{provision,uart_simulator,platform_simulator}/`、`media/src/`、`web/src/`、`updater/src/`、`packaging/`、`scripts/init.d/`。
  2. 顶层 `Makefile`（唯一入口，不递归）＋ `mk/rules.mk`（`-std=c11 -Wall -Wextra -Werror -ffunction-sections -fdata-sections`、`-MMD -MP` 自生依赖、`-Wl,--gc-sections -Wl,--no-undefined`）＋ `mk/toolchain-host.mk` / `mk/toolchain-tina-arm.mk`。
  3. 目标：`make`（host Debug）、`make arm`（`CROSS=arm-linux-gnueabi-`，可覆盖 `SYSROOT`）、`make test / asan / fuzz / package / clean / help`；产物落 `build/host/`、`build/arm/`。
  4. 库目标按 §15.5：`libivcore.a`（仅 libc）→ `libivhal.a` → `libivmodules.a` → 链出 `ivsboxd`，链接顺序即依赖方向。
  5. 从 git 历史恢复 `.clang-format`；新建 `ivsbox/.gitignore`（排除 `build/`）。
  6. 写最小 `src/app/main.c`（打印版本占位）让整条构建链有东西可编。
- **怎么验证**：
  - Host：`make` 产出 `build/host/ivsboxd` 并可运行；`make test`（暂无测试时报告 0 用例即通过）。
  - VM：`make arm` 产出 `build/arm/ivsboxd`，`file` 确认 ARM ELF。
  - 上板：pscp 传 `/tmp`，plink 执行输出版本占位，COM4 观察。
  - `make clean` 后 `git status` 干净（无散落 `.o`）。

### S2 基础件：错误码 / 日志 / 单调时钟 / 版本

- **实现什么**：四个全局基础模块（进 `libivcore`/`libivhal`）。
- **怎么实现**：
  1. `iv_err`（`src/core/iv_err.c` + `include/ivsbox/iv_err.h`）：错误码段划分（core/hal/link/proto/netmgr/probe/media/web 各一段），`iv_strerror()` 返回稳定字符串。
  2. `iv_log`（`src/core/iv_log.c`）：级别宏 `LOG_ERR~LOG_DEBUG`，输出到 stderr；板端有 syslogd 时转 `syslog(3)`；字段：时间、级别、模块、事件码；带"首次/计数/恢复"抑制辅助宏（同类事件 60s 内只打首次与计数）。
  3. `iv_clock`（`src/hal/iv_clock.c`）：`clock_gettime(CLOCK_MONOTONIC)` 毫秒/微秒接口，全工程禁止直接用系统时间做时长测量。
  4. `iv_version`（`src/core/iv_version.c`）：版本串由 Makefile 注入（`make` 时取 git 短哈希传 `-DIV_GIT_VER`）；`ivsboxd --version` 可打印。
- **怎么验证**：`tests/unit/test_basic.c`——错误码字符串非空且唯一；日志抑制：同一事件刷 100 次只出 2 行（首次+计数）；时钟单调（连续调用差值≥0）；`./ivsboxd --version` 与 `git rev-parse --short HEAD` 一致；`make asan` 全绿。

### S3 CRC

- **实现什么**：帧校验基础件。
- **怎么实现**（`src/core/iv_crc.c` + `iv_crc.h`）：zlib `crc32` 薄包装（`-lz`，登记进 Makefile 链接；最终口径由架构 §18.2 冻结的现网帧决定，现网若用 CRC16 届时在此层替换，不影响上层）；接口 `iv_crc32(buf,len,seed)` 支持分段累计。
- **怎么验证**：`tests/unit/test_crc.c`——标准测试向量（`123456789` → `0xCBF43926`）、空串、分段累计与一次算完等价、超长缓冲；板端对同一输入输出与 Host 一致（交叉验证）。

### S4 Reactor（epoll 事件循环）

- **实现什么**：`ivsboxd` 的单线程事件核心，一切 fd 事件的分发中心。
- **怎么实现**（`src/core/iv_reactor.c` + `iv_reactor.h`）：
  1. 事件基类 `iv_event_t`：fd、回调、用户数据、active/oneshot/pending 标记；`iv_reactor_t`：epoll fd、事件数组、当前时间、运行标志。
  2. 接口：`iv_reactor_create/destroy`、`iv_reactor_add(reactor,fd,events,cb,arg)`、`mod/del`、`iv_reactor_run`（主循环，**每轮递增原子进度号**——S6 健康线程依赖）。
  3. 定时器：最小堆管理 `iv_timer_t`；一个 `timerfd` 挂进 reactor，到期统一触发过期回调；`iv_timer_add(timeout_ms,cb,arg)` / `iv_timer_cancel`。
  4. 信号：`signalfd` 纳入 reactor，屏蔽 SIGTERM/SIGINT/SIGPIPE，回调里做优雅退出。
  5. 单次回调约束：只做解析、状态更新、分发；禁止 DNS、同步 SNMP/ONVIF、长文件 IO（这些走 S5 慢任务池）。
- **怎么验证**：`tests/unit/test_reactor.c`——eventfd 自触发、多 fd 注册触发顺序、`del` 后不回调、重复 `add` 报错、timer 到期与取消、SIGTERM 优雅退出；`make test` 全绿后上板跑一个挂 timerfd 每秒打日志的最小 main，COM4 观察输出节奏。

### S5 慢任务池

- **实现什么**：固定 2 worker 的有界队列，承接一切不可控阻塞操作。
- **怎么实现**（`src/core/iv_taskpool.c/.h`）：
  1. 队列定长（16）；满时提交立即返回 `IV_EBUSY`，不排队不建新线程。
  2. 任务结构带：截止时间、取消标志、结果缓冲及长度上限、完成回调（经 `eventfd` 回传 Reactor，worker 绝不碰全局业务状态）。
  3. `iv_taskpool_submit / cancel / destroy`（destroy 先置取消标志再 join）。
- **怎么验证**：`tests/unit/test_taskpool.c`——灌 20 个 sleep 任务验证 `IV_EBUSY`、取消后完成回调不再执行、eventfd 回传顺序、destroy 无死锁（ASan+ThreadSanitizer）；板上跑睡眠占位任务，主循环进度号持续递增（Reactor 不被阻塞的证据）。

### S6 健康线程 + 看门狗门控

- **实现什么**：独立健康线程，只有"主循环在走 + 慢任务没死锁"才喂 `/dev/watchdog`。
- **怎么实现**（`src/hal/iv_watchdog.c` + `src/app/health.c`）：
  1. 健康线程每秒比对：Reactor 原子进度号（S4 已埋）、taskpool 各 worker 进度号、关键链路时间戳。
  2. 全部健康 → `ioctl(fd, WDIOC_KEEPALIVE)`；任一超预算 → 记录最小故障信息（模块名＋进度号快照）→ 停止喂狗，**不得**尝试替主循环跑业务。
  3. 看门狗超时可配（进 S8 配置），留出 procd 重启窗口。
- **怎么验证**：板上 `ioctl(WDIOC_SETTIMEOUT)` 设 10s；`kill -STOP <pid>` 模拟主循环卡死 → 10s 后 COM4 观察整机复位；恢复正常时不复位。Host 上用假 watchdog fd 单测判定逻辑（不真喂狗）。

### S7 IPC：消息头 + UDS SEQPACKET 通道

- **实现什么**：`ivsboxd` 作为服务端的本地 IPC 完整通道（帧头＋载荷＋超时＋对端鉴权）。
- **怎么实现**（`include/ivsbox/iv_ipc.h` + `src/core/iv_ipc_srv.c`）：
  1. 消息头 `ivs_ipc_hdr_t`（架构 §5.1：magic 'IVSB'、version、type、flags、request_id、payload_len，定长、显式对齐）。
  2. `socket(AF_UNIX, SOCK_SEQPACKET)`；路径 `/var/run/ivsbox/ctl`；权限 0660。
  3. `SO_PEERCRED` 校验对端 uid/gid 白名单；载荷 JSON（选型随本步：候选 cJSON 单文件库，登记待安装清单；若镜像确定不放，先改架构文档再换定长二进制）。
  4. 请求带超时与 request_id 关联；长任务立即回 `task_id`，结果走事件通知。
- **怎么验证**：`tests/unit/test_ipc.c`——头编解码、sizeof/偏移锁定、半包拒绝、超长拒绝；集成——client 连接：正常收发、超时、非授权 uid 拒绝（切普通用户跑 client）；板上用临时调试命令触发 `system.snapshot` 返回快照。

### S8 配置模块

- **实现什么**：`/data/ivsbox/config/` 下配置的读取、校验、原子写、热更新通知。
- **怎么实现**（`src/modules/config/iv_config.c`）：
  1. 格式按架构 §10.2：`platform.json` / `network.json` / `media.json` 等分职责拆分（解析库随 S7 选型）；schema 版本＋内容版本＋校验值字段。
  2. 原子写：tmp → `fsync` → `rename` → `fsync` 目录；写前完整校验（类型/范围/引用/跨字段），失败保留旧配置返回错误码。
  3. 热更新：`inotify` 挂进 Reactor；变更以事务通知各模块，**不能应用的字段不得部分生效**。
  4. 密钥类进 `secure/`（0600），普通配置只存引用。
- **怎么验证**：`tests/unit/test_config.c`——写中途留 tmp 不 rename（模拟断电）后重读仍为旧值、非法值拒绝、inotify 触发回调、热更新全有或全无；板上改配置文件，COM4 观察热生效日志。

### S9 SQLite 封装

- **实现什么**：`control.db` 单写者封装，供档案/审计/网络历史用。
- **怎么实现**（`src/core/iv_db.c`）：链接 `-lsqlite3`（VM sysroot 已有，S1 验证）；WAL、`busy_timeout`、短事务 helper（begin/commit/rollback 宏）；`sqlite3_open_v2` 仅主控使用；库文件 `/data/ivsbox/db/control.db`；损坏检测（header 校验失败改名 `.corrupt` 重建，不覆盖现场）。
- **怎么验证**：host 单测建表/事务回滚/WAL 并发读不阻塞；板上生成 `-wal/-shm`，写入后断电重启 `PRAGMA integrity_check` 通过。

### S10 ivsboxd 骨架装配 + procd

- **实现什么**：把 S2~S9 装配成可运行的 `ivsboxd` 骨架，并纳入 procd 守护。
- **怎么实现**：
  1. `src/app/main.c`：启动顺序＝日志→配置→SQLite→taskpool→Reactor→IPC 服务→健康线程；`main` 只做装配，业务逻辑全在模块。
  2. `scripts/init.d/ivsboxd`：`USE_PROCD=1`；`procd_set_param respawn 3600 5 0`；`procd_set_param command /opt/ivsbox/current/bin/ivsboxd`；stderr/stdout 接 logd；普通用户运行。
  3. `make package` 把 `ivsboxd`＋init 脚本归集到 `packaging/`（后续 OTA 用）。
- **怎么验证**：板上 `/etc/init.d/ivsboxd enable && start`；`kill -9` 后 procd 自动拉起（logread 证据）；`stop` 干净退出；IPC 快照可查；S6 看门狗场景复测确认装配后仍生效。

**M1 退出条件**：`make` 与 `make arm` 两类构建通过；板端 IPC 收发可验证；看门狗门控生效；procd 守护生效。

## M2 核心链路（UART + 平台 + GPS）

前置：架构 §18.1（平台帧）与 §18.2（UART 帧）冻结。未冻结时先做 S2.7 模拟器一侧。

### S2.1 hal/serial 串口

- **实现什么**：`termios` raw 模式串口，纳入 Reactor。
- **怎么实现**（`src/hal/iv_serial.c`）：`cfmakeraw` 后显式关 `CRTSCTS`、`VMIN=0/VTIME=0`；波特率/数据位参数化；**`flock(/var/run/ivsbox/serial.lock)` 进程单实例锁**防双实例抢串口；`open` 非阻塞 + `O_NOCTTY`。
- **怎么验证**：host 用 `socat -d -d pty,raw,echo=0 pty,raw,echo=0` 造虚拟串口对灌数据；板上短路环自收发 + `stty -F /dev/ttyS3` 核对参数生效。

### S2.2 UART 帧解析器

- **实现什么**：对字节流的成帧：半包、粘包、噪声重同步、长度上限、校验失败、帧超时。
- **怎么实现**（`src/modules/link/iv_frame.c`，core 层无 HAL 依赖）：状态机（SYNC→HDR→LEN→BODY→CRC）；噪声丢弃到下一同步字；校验用 S3 的 `iv_crc`；帧缓冲定长，超长整帧丢弃计数。
- **怎么验证**：`tests/unit/test_frame.c`——正常帧/两帧粘包/半包跨 read/中间插噪声/坏 CRC/超长/帧间隔超时全用例；`make fuzz` 灌随机字节 10 分钟无 crash/挂死（ASan 下）。

### S2.3 UART 可靠层

- **实现什么**：兼容现有采集板协议的命令级可靠收发。
- **怎么实现**（`src/modules/link/iv_link.c`）：协议有请求号+ACK → 直接做超时重传＋去重表；没有 → 命令级确认＋状态回读；**门锁/电源类控制幂等或带事务号**（防重传重复动作）；链路恢复后发全量状态同步请求重建镜像（对接 S2.6）。
- **怎么验证**：与 `uart_simulator`（S2.7）对联：正常收发、丢 ACK 触发重传、重复帧被去重、断链重连后镜像同步；真实采集板可用时冒烟。

### S2.4 平台协议

- **实现什么**：与云平台的私有协议栈：连接、表驱动命令路由、分级发送队列、断线补传。
- **怎么实现**（`src/modules/proto/`）：
  1. 连接管理挂 Reactor：非阻塞 connect、断线退避重连（1s→2s→…→60s 封顶）。
  2. 命令路由表：`{cmd, mode(本地/转发采集板/本地并转发), handler}`；未知命令按白名单决定是否透传（禁无条件透传）。
  3. 发送队列四级：门禁/控制 > 告警 > 状态 > 媒体；每级字节＋条目上限，满则丢最低优先级并计数。
  4. 每请求带关联号、超时、幂等键。
- **怎么验证**：`platform_simulator`（S2.7）对联：注册/心跳/上行告警/下行控制（含转发采集板路径）/未知命令按白名单处置/断线重连；VM 上 `tc netem loss 20%` 验证超时重传与队列降级。

### S2.5 GPS 与时间

- **实现什么**：定位读取上报与系统时间源管理。
- **怎么实现**（`src/modules/gps/`）：板上有 `gpsd` 则读其 socket；否则最小 NMEA 解析器（`GGA/RMC` 子集，其他语句直接跳过）；首次有效定位立即上报，此后按位移阈值或最长周期；时间源优先级平台/GPS/NTP/RTC 可配，小偏差渐进调（`adjtime`），大偏差审计后 `settimeofday`。
- **怎么验证**：host 用录制的 NMEA 样本回放单测（有效/无效/半句/乱序）；板上接 GPS 模组（或串口灌样本）看上报报文与 `date` 跳变日志。

### S2.6 状态镜像

- **实现什么**：采集板全部 IO/状态在 `ivsboxd` 内存中的权威镜像。
- **怎么实现**（`src/modules` 内 `status.c`）：镜像结构体＋变更版本号；UART 事件与全量同步两条更新路径都收敛到 Reactor 单写者；快照接口供 IPC `system.snapshot` 与平台上报。
- **怎么验证**：单测——事件序列后镜像字段断言、全量同步覆盖事件残留；集成——断开重连 simulator 后镜像与 simulator 侧一致。

### S2.7 模拟器

- **实现什么**：`tools/uart_simulator`、`tools/platform_simulator` 两个可执行。
- **怎么实现**：uart_simulator——可脚本化（命令文件：延时/发帧/坏帧/静默），监听串口或 pty；platform_simulator——TCP 服务端，按平台协议应答，支持丢包/延迟/断连注入开关。
- **怎么验证**：自测即 S2.3/S2.4 的验证载体；另做一轮故障注入（坏帧率 10%、静默 30s）确认主控不死、不泄漏 fd。

**M2 退出条件**：丢包、半包、重连、重同步测试通过（模拟器口径）；真实对端可用时冒烟通过。

## M3 网络管理

前置：§18.3（4G 模组、拨号栈、双 WAN 网卡名）确认。

### S3.1 rtnetlink 监听

- **实现什么**：链路/地址/路由变化的内核事件源。
- **怎么实现**（`src/hal/iv_netlink.c`）：`socket(AF_NETLINK, SOCK_RAW, NETLINK_ROUTE)` 订阅 `RTMGRP_LINK/IPv4_IFADDR/IPv4_ROUTE`；解析事件挂 Reactor；对外回调 carrier up/down、地址增删、默认路由变更。禁止轮询解析 `ifconfig`。
- **怎么验证**：VM/板上 `ip link set eth0 down/up`、`udhcpc` 触发地址变化，日志按序输出事件；对照 `ip monitor` 输出一致。

### S3.2 统一探活引擎

- **实现什么**：主网/双 WAN/摄像机共用的四层探活与统计判定。
- **怎么实现**（`src/modules/probe/`）：
  1. 链路层＝S3.1 事件；网络层＝raw socket ICMP（`CAP_NET_RAW`）；传输层＝非阻塞 TCP connect 完成即断开；应用层＝心跳/RTSP OPTIONS/SNMP GET 任一。
  2. 统一输出结构：状态、原因码、最近 RTT、滑动平均、丢包率、连续成败次数、最近成功时间。
  3. ICMP 被禁（无 CAP 或被墙）时，TCP/应用层成功仍判可用。
- **怎么验证**：host 单测统计滑窗；VM 上 `tc netem delay 200ms loss 5%` 注入后 RTT/丢包率读数与 `ping` 旁证一致；拔网线 carrier 事件即时置 DOWN。

### S3.3 双 WAN 状态机

- **实现什么**：无线优先、故障切有线、稳定回切的确定性状态机（架构 §7.2）。
- **怎么实现**（`src/modules/netmgr/`）：状态 `WIRELESS_UP/DEGRADED/SWITCH_TO_WIRED/WIRED_UP/SWITCH_TO_WIRELESS/BOTH_DOWN`；参数（fail_n/ok_n/hold_s）进配置；切换执行 §7.2 七步事务：冻结低优先级发送 → netlink/策略路由切换默认出口 → **关闭绑定旧接口的 TCP（含平台连接与远程流）** → 新接口重连 → 鉴权恢复 → 按优先级补传 → 稳定期后恢复媒体大流量。
- **怎么验证**：模拟器＋netem：无线断→连续 fail_n 后切有线、平台连接从新出口重建、断线队列补传不重不丢；无线恢复 hold_s 后回切；双断进 BOTH_DOWN 只告警不动作。对照架构 §16.2 场景 1/2。

### S3.4 持久上报队列

- **实现什么**：断线期间待上报数据的落盘有界队列。
- **怎么实现**（`src/modules/proto/queue.c`）：目录 `/data/ivsbox/queue/`，按序号分段文件＋内存索引；容量上限（字节＋条目）满则按优先级丢弃最低级并计数；恢复后按序补传，确认后删除段文件。
- **怎么验证**：单测——写入/恢复/超限丢弃/补传确认删除；集成——S3.3 切换场景中补传无丢失无重复（对端 simulator 校验序号连续）。

**M3 退出条件**：拔线、弱网、回切、补传验收通过（§16.2 场景 1/2）。

## M4 设备管理

前置：§18.4（摄像机/交换机品牌、数量、RTSP 地址、ONVIF 能力、SNMP OID 清单）。

### S4.1 摄像机三层探测

- **实现什么**：ICMP→TCP→RTSP 逐层探测，记录最接近业务的失败原因。
- **怎么实现**（`src/modules/probe/cam_probe.c`）：复用 S3.2 引擎；RTSP 层发 `OPTIONS`/`DESCRIBE`（仅取状态码与头，不拉流）；探测任务进慢任务池。
- **怎么验证**：对实验室摄像机（海康 192.168.1.200、大华 .106/.108）断电/断网/改密码三种故障，确认原因码分层正确；netem 注入高延迟不阻塞 Reactor。

### S4.2 ONVIF 与一机一档

- **实现什么**：发现、档案补齐、`control.db` 档案库。
- **怎么实现**（`src/modules/device/`）：选型优先镜像内已有 SOAP/HTTP 组件（无则登记待安装清单，先做直连 HTTP `GetDeviceInformation`）；WS-Discovery（UDP 组播 239.255.255.250:3702）挂 Reactor；档案主键＝MAC/序列号，IP 为可变属性；口令只存 `secure/` 引用，导出档案不含凭据。
- **怎么验证**：真实品牌样本：发现→建档→字段完整（品牌/型号/序列号/MAC/Profile/OSD）；改 IP 后档案不重复；导出文件 grep 无口令。

### S4.3 SNMP 采集

- **实现什么**：摄像机 CPU/内存/码率、交换机端口/流量统一字段采集。
- **怎么实现**（`src/modules/snmp/`）：优先 `net-snmp` 裁剪或轻量库（登记选型）；OID 模板按品牌/型号存配置；映射统一字段 schema；交换机标准 IF-MIB 打底，厂商扩展（温度/PoE）走模板。
- **怎么验证**：对实验室设备 `snmpwalk` 旁证数值一致；模板缺失时报"未知型号"而非乱猜；采集超时不阻塞（慢任务池验证）。

### S4.4 自愈策略引擎

- **实现什么**：故障确认→断电重启→验证→熔断的完整状态机（架构 §7.6）。
- **怎么实现**（`src/modules/recovery/`）：规则字段：目标/触发条件/确认方式/动作/电源通道/断电时长/重试次数/冷却/时间窗/熔断上限；四道保护——冷却、每小时与每天限频、**上游关联**（≥N 台同类同时掉线先查交换机/主网，不动作）、超限熔断只告警；动作为经 UART 下发的电源通道控制（对接 S2.3，带事务号幂等）。
- **怎么验证**：单测规则引擎状态迁移全路径；集成——simulator 模拟单摄像机故障→确认→断电→恢复；模拟 8 台同时掉线→判定上游不动作；连续超限→CIRCUIT_OPEN 只告警。对照 §16.2 场景 3。

### S4.5 门锁与门事件

- **实现什么**：鉴权开锁、门事件上报、联动抓图触发（抓图本体在 M6）。
- **怎么实现**（`src/modules/access/`）：开锁请求带事务号＋来源鉴权＋有效期＋去重表；门磁事件（UART 上送）立即上报平台不等抓图；审计入 `control.db`；断电后锁状态语义按硬件安全要求处理，不假设默认上锁。
- **怎么验证**：simulator 注入门磁事件与 ACK 交互：重放同一事务号被拒、过期授权被拒、门开上报时延 < 1s（本地口径）；审计记录字段完整。对照 §16.2 场景 4 前半。

**M4 退出条件**：目标品牌兼容矩阵（发现/探测/ONVIF/SNMP/档案）通过；§16.2 场景 3/4 通过。

## M5 Web 与工装

### S5.1 ivsbox-web 服务

- **实现什么**：独立 Web 进程：静态页＋REST＋受控代理，无特权运行。
- **怎么实现**（`web/`）：选型固定一种成熟嵌入式 HTTP 库或 uhttpd（登记选型并固化版本）；监听端口可配；上限：连接数、请求体大小、上传大小、代理响应大小、各类超时；数据一律走 IPC（M1-S7）请求 `ivsboxd`/`ivsbox-media`，不直接开数据库、不写配置文件；procd 守护、独立非特权用户。
- **怎么验证**：`ab -n 10000 -c 50` 压测无 fd 泄漏（`ls /proc/<pid>/fd | wc -l` 稳定）；超限请求被拒返回稳定错误码；kill 后 procd 拉起且 `ivsboxd` 不受影响。

### S5.2 REST API

- **实现什么**：§9.1 八页面对应的全部 API。
- **怎么实现**：`GET` 查询、`POST` 建任务（长任务返回 task_id）；全部写操作鉴权＋审计（经 IPC 落 `control.db`）；高风险操作（开锁/电源重启/升级/身份写入/代理授权）二次确认；错误码表独立文档化；**禁止** API 拼接 shell。
- **怎么验证**：curl 全接口回归脚本（正常/未登录/越权/超长输入）；重放拦截（nonce/时间窗）；审计记录逐条核对。对照 §16.1 安全测试"鉴权绕过、重放、SSRF"。

### S5.3 八个页面

- **实现什么**：总览/网络/摄像机/设备档案/交换机/媒体/配置/运维。
- **怎么实现**：静态资源 `web/static/`，纯 HTML+JS+轮询或 SSE（无重框架）；配置页走 S5.4 事务接口；媒体页在 M6 前显示"未启用"占位。
- **怎么验证**：浏览器逐页走查（数据来自 IPC 快照）；配置页提交非法值被前端与后端双重拦截。

### S5.4 配置事务与热更新（Web 路径）

- **实现什么**：Web 改配置的完整链路：提交→校验→原子写→事务通知→生效确认。
- **怎么实现**：复用 M1-S8 配置模块；Web 只发 IPC `config.apply`（带版本号防覆盖更新，ETag 语义）；失败保留旧配置并回显明确错误。
- **怎么验证**：改探活参数→模块日志确认热生效且无部分生效；并发双写冲突被版本号拦截。

### S5.5 ivsbox-provision 出厂工装

- **实现什么**：设备 ID/MAC 写入工具，量产口径。
- **怎么实现**（`tools/provision/`）：独立可执行，仅工厂模式可运行（`/data/ivsbox/factory/` 存在 `enable_provision` 标记时）；写 `factory/`（0600）＋锁定位（或受控维护流程）；量产后入口关闭；不进日常 procd 自启。
- **怎么验证**：工装流程演练——写入→重启→`iv_version`/平台上报携带新身份；二次写入被拒；删除标记后运行直接退出。

**M5 退出条件**：权限与审计测试通过；S5.2 回归脚本全绿。

## M6 媒体与音频

前置：§18.5（录像路数/码率/SD 容量/保留周期）；S6.6 另需 §18.6（音频硬件与广播需求）。

### S6.1 ivsbox-media 骨架

- **实现什么**：媒体进程：IPC 服务端＋有界任务队列＋资源限额。
- **怎么实现**（`media/src/`）：控制循环处理 IPC（`record.start/stop`、`snapshot.take`、`media.list`、`audio.play/stop`）；每路 RTSP 会话独立 pipeline，数量受 `media.max_channels`；崩溃只重启自身（procd），`ivsboxd` 侧 IPC 心跳检测"存在但不响应"并主动要求重启。
- **怎么验证**：IPC 心跳丢失→`ivsboxd` 请求 procd 重启 media（logread 证据）；media kill -9 循环 20 次主控业务不中断。

### S6.2 抓图

- **实现什么**：门事件/平台/Web 三来源的抓图落盘与上报。
- **怎么实现**：优先摄像机 HTTP 抓拍接口（海康 ISAPI/大华 CGI 适配层），失败退 RTSP 关键帧；多路默认串行或低并发（配置）；临时文件 `fsync`＋`rename` 原子落盘→`media.db` 索引→IPC 完成事件→`ivsboxd` 上报；缩略图生成（选型登记）。
- **怎么验证**：开门事件触发抓图全链路时延与成功率（实验室 20 次）；抓图失败仅告警不影响门事件上报（§16.2 场景 4 后半）；断电瞬间的 tmp 文件不进索引。

### S6.3 断网录像

- **实现什么**：主网＋平台双确认后的本地 RTSP 录像。
- **怎么实现**：触发条件＝S3.2 探活判定主网与平台均不可用且保持配置时长；恢复后延迟停止防抖动；**码流直封装不转码**（FFmpeg libavformat remux）；1~5 分钟切片，关闭成功后 `rename`；每会话建连/无数据/读写/停止四类超时；总路数、总码率、写盘带宽上限。
- **怎么验证**：断网场景录制→恢复→文件可被 VLC/ffprobe 正常解析且时间连续；拔 SD 卡录制中→进程不崩、恢复挂载后继续；§16.2 场景 5。

### S6.4 视频读取（上传/下载）

- **实现什么**：录像文件的远程读取通道。
- **怎么实现**：方式一：设备主动向平台文件服务分片上传（4G 私网主路径，限速可配）；方式二：HTTP Range 下载（供 Web/授权通道，支持 Range/ETag/校验值/限速/取消）；**与大文件传输和控制在传输层隔离**，不与控制指令共队列。
- **怎么验证**：上传中断续传序号正确；Range 请求 206 与全量 sha256 一致；限速生效（`iftop` 观测不影响并行的平台心跳）。

### S6.5 SD 卡策略

- **实现什么**：存储水位、清理、异常检测。
- **怎么实现**：定时巡检挂载/只读/IO 错误/剩余空间（`statfs`）；水位线：85% 清理最旧可删→90% 拒新任务→95% 停录告警→70% 恢复；三类保留优先级（抓图>告警录像>普通录像）；按切片关闭同步而非每包 `fsync`。
- **怎么验证**：灌数据到水位线触发各级动作（日志＋行为）；满盘/只读/拔卡注入时控制业务不受影响（§16.2 场景 6）。

### S6.6 音频广播（前置：§18.6 确认）

- **实现什么**：`audio_sink` 统一接口与优先级播放。
- **怎么实现**：sink 实现：ALSA/I2S 本地、网络音柱、摄像机语音对讲、采集板预置资源（按 §18.6 结论裁剪）；任务字段：编码/音量/优先级/有效期/目标；紧急>告警>通知可抢占；实时流配抖动缓冲与无数据超时。
- **怎么验证**：按确认后的硬件形态定（本地功放放音、抢占时延、断流超时停止）。

**M6 退出条件**：资源上限与异常恢复通过（§16.2 场景 5/6）。

## M7 OTA 与加固

前置：§18.7（OTA 范围：应用/采集板固件/系统镜像）。

### S7.1 升级包格式与验签

- **实现什么**：带强制签名的升级包格式与验签器。
- **怎么实现**：包内清单：产品型号、硬件版本范围、软件版本、最低可回滚版本、文件清单、SHA-256、数字签名（mbedTLS/OpenSSL，Ed25519/ECDSA）；设备内置只读公钥；`ivsboxd` 只协调（收命令/下载/上报进度），验签安装归 `ivsbox-updater`。
- **怎么验证**：正常包通过；篡改单字节被拒；型号不匹配被拒；无签名被拒（§16.2 场景 9）。

### S7.2 ivsbox-updater 与双版本切换

- **实现什么**：root 按需运行的安装器，应用级 A/B。
- **怎么实现**（`updater/`）：目录 `/opt/ivsbox/releases/<ver>/`、`current`/`previous` 符号链接；流程：下载到临时目录→验签→解压新版目录（查权限/架构/依赖）→临时符号链接 `rename` 原子切 `current`→写 `/data/ivsbox/ota/pending.json`→重启业务；新版本健康自检（平台/UART/配置/DB/媒体 IPC）通过才确认，否则启动包装程序恢复 `previous`。
- **怎么验证**：正常升级路径全链路；升级中掉电→重启后旧版本可运行；新版自检失败→自动回滚（§16.2 场景 8 前半）。

### S7.3 回滚与启动包装

- **实现什么**：开机自检与自动回滚兜底。
- **怎么实现**：`current/bin/ivsboxd` 由包装脚本启动，记录 `bootcount`；连续 N 次启动失败或自检超时→切回 `previous` 并置告警；应用级回滚不用 U-Boot rootfs 槽位冒充（系统级 A/B 另立项，见架构 §11.3）。
- **怎么验证**：`bootcount` 超限注入→回滚；回滚后平台收到版本回退事件。

### S7.4 故障注入加固

- **实现什么**：§16.1 故障注入类目的全量通过。
- **怎么实现**：按清单执行——弱网、双网断开、串口拔出、SD 满/拔卡、进程卡死（SIGSTOP 各进程）、掉电（升级中/录像中/写库中）。
- **怎么验证**：每项注入后系统行为符合架构预期并留测试记录（§16.2 场景 7）。

### S7.5 长稳测试

- **实现什么**：≥72 小时连续运行。
- **怎么实现**：脚本化周期触发网络切换、媒体启停、IPC 查询；监测 RSS/fd/线程数/DB 大小斜率。
- **怎么验证**：72h 无重启、无 OOM、资源曲线平稳。

**M7 退出条件**：断电回滚正确＋72h 长稳通过＋§16.2 场景 7/8/9 通过。
