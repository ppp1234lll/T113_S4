1. 目的与范围

目的：在板端与实验室环境对已交付的 M1~M9 功能做一次完整功能验收，确认每项功能按设计工作，并对架构 §16.2 的 10 个核心场景给出明确结论（通过 / 阻塞 + 原因）。

范围内：主控与守护、配置、采集板串口、GPS、双 WAN 与平台上报、设备管理（探测 / SNMP / 断电重启 / 箱门抓拍）、Web 八页面与鉴权审计、媒体与 SD、OTA、远程通道、control.db、设备身份工装、版本与运维接口。

范围外：平台服务端改造、单片机固件、音频广播（S6.6 已冻结）、量产工装产线流程。详见 §8。

6. 缺陷分级与准出

级别定义示例
P0 阻断核心业务中断或数据不可恢复掉网后不恢复、主控不重启、补传丢/重、OTA 变砖、越权可访问、误动作导致设备断电
P1 严重主要功能不可用，无绕行手段页面打不开、录像不出、采集无数据、SD 拔卡致控制业务中断
P2 一般功能可用但有明确偏差显示单位错误、告警等级不准、单页数据不同步、时延超标
P3 轻微文案、样式、提示语错别字、按钮位置、默认值提示不清晰

准出条件（全部满足才算通过）：

  1. P0 = 0，P1 = 0，P2 ≤ 3 且每条有书面规避方案。
  2. 自动化层全绿：test / asan / tsan / analyze 0 报告，itest 无 FAIL（SKIP 不计通过）。
  3. 架构 §16.2 十个场景逐条有结论（通过 / 阻塞 + 原因 + 计划）。
  4. 72 h 长稳无非预期重启，RSS 与 fd 斜率在阈值内。
  5. §8 遗留项已单独登记，不与本轮结论混淆。
