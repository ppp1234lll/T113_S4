这份手册只干一件事：把设备树里的 UART1 打开，让板端出现 /dev/ttySAC1。 GPS 模组挂在 UART1，引脚 PD21 / PD22，链路参数 9600 8N1 无流控（2026-09-30 用户给的硬件事实）。

适用：编译 VM tqt113（embedsky 用户）+ SDK 根 /opt/Embedsky/mount/t113_tina。 不涉及 GPS 的 NMEA 解析、校时、上报（那些是 ivsbox 代码侧，另见 docs/代码说明.adoc）。

0. 先把原因说清楚：为什么出厂镜像里没有 ttySAC1

不是谁改坏了，而是 SDK 出厂配置里 UART1 就是关的，并且它的引脚组是空的：

位置出厂状态后果
&uart1 节点status = "disabled";内核不注册 uart1 设备 ⇒ 不建 /dev/ttySAC1
uart1_pins_a/b// pins = "PE10", "PE11";（被注释）pin group 为空 ⇒ 就算把 status 改成 okay，PD21/PD22 也不会切到 UART1

实证：反编译 16:59 那版固件里的 dtb，/soc@3000000/uart@2500400（device_type="uart1"，serial1 别名指向它）就是 status = "disabled"；uart0（serial0）同样是 disabled。所以板端只会有 ttySAC2/3/4/5，本来就没有 ttySAC0 与 ttySAC1。

这条早已登记为遗留项 P1-13（ivsbox/docs/代码说明.adoc:579："GPS 走 UART1（PD21/PD22），但设备树里 uart@2500400 是 disabled ⇒ /dev/ttySAC1 不存在……启用须改 dts 并重烧 boot"）。 与 frpc 编入镜像、与早前 uart0 的那次还原都无关（uart0 已还原成出厂 #if 0，当时重编出的 dtb 与上一版逐字节相同）。

⚠ SDK 里有两份名叫 board.dts 的文件，别改错：

① 内核树那份（本手册要改的，76337 字节）：.../kernel/linux-5.4/arch/arm/boot/dts/board.dts —— arch/arm/boot/dts/Makefile 里写着 dtb-$(CONFIG_ARCH_SUN8IW20) += board.dtb，编进固件的就是它。

② 板级配置目录那份（56242 字节，不参与编译）：.../device/config/chips/t113/configs/evb1_auto/linux-5.4/board.dts （device/config/.../evb1_auto/board.dts 是指向它的软链）。mkcmd.sh 里那个"从配置目录拷到内核树"的 cp 位于 prepare_mkkernel() 内，而该函数的调用处全部被注释掉，所以这份不会覆盖内核树。

判据（已实测）：两份差 1123 行；固件 dtb 里含 c906_ddr 节点，只在内核树那份里有（配置目录那份为 0 处）。

【官方】佐证：《TQT113_linux_系统开发手册》§2.1.1「常用配置文件介绍」把 kernel/linux-5.4/arch/arm/boot/dts/board.dts 直接列为内核设备树 （同表里 device/config/chips/t113/configs/evb1_auto/linux-5.4/config-5.4 是内核配置单）—— 要改的就是这一份，与本手册结论一致。

2. Step 1 —— 备份（1 条命令）

先给原文件留一份带时间戳的副本，回滚时直接用。

cp -a /opt/Embedsky/mount/t113_tina/kernel/linux-5.4/arch/arm/boot/dts/board.dts /tmp/board.dts.bak-$(date +%m%d-%H%M)

本次执行的备份文件：/tmp/board.dts.bak-1016-0833，其 md5 91d6efcad198e1521ca6081344c1b53a（＝ SDK 出厂原始文件）。

3. Step 2 —— 改 4 处（3 条 sed，各一条一行）

三条命令顺序执行、互不依赖，可以逐条粘贴。

3.1 补上 uart1 的引脚（一条命令同时改两处注释行）

sed -i 's|^[[:space:]]*//[[:space:]]*pins = "PE10", "PE11";|\tpins = "PD21", "PD22";|' /opt/Embedsky/mount/t113_tina/kernel/linux-5.4/arch/arm/boot/dts/board.dts

说明：文件里只有这两行含 PE10/PE11（uart1_pins_a 与 uart1_pins_b），一次全改。若脚本文件开头是 // pins = "PE10", "PE11";，说明还没改过；改完再跑一次不会有任何副作用（匹配不到即不动）。

3.2 打开 uart1 控制器

sed -i '/^&uart1 {/,/^};/{s|^[[:space:]]*status = "disabled";|\tstatus = "okay";|}' /opt/Embedsky/mount/t113_tina/kernel/linux-5.4/arch/arm/boot/dts/board.dts

说明：地址范围锁定在 &uart1 { 到它自己的 }; 之间，只改这个节点里的 status，不会碰到 uart2/uart3 等。

3.3 让出 PD22：关掉 pwm7（背光）

sed -i '/^&pwm7 {/,/^};/{s|^[[:space:]]*status = "okay";|\tstatus = "disabled";|}' /opt/Embedsky/mount/t113_tina/kernel/linux-5.4/arch/arm/boot/dts/board.dts

3.4 改完应该长这样

位置（改前行号）改前改后
uart1_pins_a（448）// pins = "PE10", "PE11";pins = "PD21", "PD22";
uart1_pins_b（455）// pins = "PE10", "PE11";pins = "PD21", "PD22";
&uart1（861）status = "disabled";status = "okay";
&pwm7（3093）status = "okay";status = "disabled";

⚠ 为什么必须关 &pwm7：PD22 在 SDK 默认配置里被 LCD 背光占用。

证据链：pwm7_pin_a { pins = "PD22"; function = "pwm7"; }（board.dts:766）＋ &pwm7 { status = "okay"; }（board.dts:3089）＋ 背光驱动通道写死为 7：drivers/video/backlight/pwm_bl.c:185 data->pwm_id = 7;；且固件 dtb 里 backlight 节点是启用状态、lcd_used = <1>。 两个驱动同时抢 PD22 会让 GPS 收不到数据（dmesg 常见 pin conflict 提示），所以用 PD22 收 GPS 前必须把 pwm7 关掉。

⚠ 若你的底板 LCD 背光确实接在 PD22，那就是硬件层面的二选一（GPS 与背光不能同时用），需要从原理图确认后改硬件。 若 GPS 实际走的是另一组脚位，把 3.1 里的 "PD21", "PD22" 换成对应脚位即可 —— 驱动表里 UART1 可选三组： PD21(TX)/PD22(RX)（mux 4）、PE10(TX)/PE11(RX)（mux 3，SDK 注释里留的原值，当前 dtb 里无人占用）、PB8(TX)/PB9(RX)（mux 7）； 换用 PE10/PE11 时 3.3 那条（关 pwm7）就不必执行。

4. Step 3 —— 核对改动（1 条命令）

diff -u /tmp/board.dts.bak-1016-0833 /opt/Embedsky/mount/t113_tina/kernel/linux-5.4/arch/arm/boot/dts/board.dts

5. Step 4 —— 编译前语法自检（2 条命令）

先自己用 cpp + dtc 走一遍设备树编译链，几秒钟就能发现括号/引号级别的错误，省掉一次 20 分钟的整包构建。

cpp -nostdinc -I /opt/Embedsky/mount/t113_tina/kernel/linux-5.4/include -I /opt/Embedsky/mount/t113_tina/kernel/linux-5.4/arch/arm/boot/dts -undef -D__DTS__ -x assembler-with-cpp -P /opt/Embedsky/mount/t113_tina/kernel/linux-5.4/arch/arm/boot/dts/board.dts -o /tmp/board.pp.dts
dtc -I dts -O dtb -o /tmp/board.check.dtb /tmp/board.pp.dts

两条都无输出、退出码 0 即通过（会有 Warning (node_name_vs_property_name) 之类的既有告警，那是 SDK 自带的，可忽略）。

grep -n -A6 '^&uart1 {' /tmp/board.pp.dts

期望看到 status = "okay";。

6.2 只改 dts 时的快速路径 ·【补充】（可选，与 6.1 二选一）

./build.sh dts
./build.sh bootimg
命令干什么本次实测
./build.sh dts只重编设备树：board.dts → board.dtb → 拷成 out/.../buildroot/sunxi.dtbrc=0，约 17 秒，sunxi.dtb 62404 → 62452 字节
./build.sh bootimg把新 dtb 压进 boot.img（内核 dtb 就装在这枚镜像里）rc=0，约 24 秒，boot.img 里新引脚串由 0 → 2 处

为什么不直接用官方的 kernel：改 dts 时整编内核（2 分 24 秒）里绝大部分时间花在与本次改动无关的内核重新编译上； dts ＋ bootimg 两条加起来 41 秒就能得到同样的 boot.img。两者等效、二选一即可： 用了 6.1 的 ./build.sh kernel 就不用跑 6.2；反过来跑了 6.2 就不必再跑 kernel（内核没动）。

⚠ 6.2 的坑：./build.sh dts 只刷新磁盘上的 sunxi.dtb，不碰 boot.img —— 必须接一条 ./build.sh bootimg 才生效。 6.1 的 ./build.sh kernel 内部已经含了这一步（mkcmd.sh 的 build_kernel() 末尾会调 build_dts false，并已产出 boot.img），所以走官方路径时不需要额外补命令。

【补充】说明：dts / bootimg 这两个 target 官方文档没写，是 SDK 里实际存在的（build/mkcommon.sh 的分派行有 dtb|brandy|bootloader|arisc|dts|kernel|modules|rtos|bootimg)， build/mkcmd.sh:1697 build_dts()、:1768 build_bootimg()）—— 本手册两条都实测过（rc=0，耗时见上表）。 若你的 SDK 里这两个 target 不存在或行为不同，一律以 §6.1 的官方路径 ./build.sh kernel 为准（设备树与内核一起编，等效且不挑版本）。

⚠ fastboot 的具体命令（分区名、参数）以《TQT113_linux_使用手册》§3.1.5 的原文为准 —— 本手册不复写，避免与官方不一致。 本手册只确保前一步的 boot.img 里确实带了新 dtb（见 §7）。

板端逐条执行（先确认设备节点，再看数据）：

ls -l /dev/ttySAC*

期望多出 /dev/ttySAC1（原来的 ttySAC2/3/4/5 仍在）。

dmesg | grep -i ttySAC

期望有 uart1/ttySAC1 注册信息；若出现 pin ... already requested 之类字样，说明 PD22 还被别的驱动占着，回头查 &pwm7 是否真的 disabled。

stty -F /dev/ttySAC1 9600 cs8 -parenb -cstopb -crtscts
timeout 3 head -c 200 /dev/ttySAC1 | xxd | head

第二条能刷出 $GNRMC/$GNGGA 之类的 NMEA 文本，就说明 GPS 链路通了。

装配侧提醒：ivsbox 打开 GPS 口必须用 /dev/ttySAC1 ＋ 9600 8N1 无流控（常量 IV_GPS_UART_BAUD）， 不能吃 iv_serial_cfg_default()（115200）的默认值，否则收不到数据；代码里刻意不提供默认串口路径。

10. 排障速查

现象原因处理
板端没有 /dev/ttySAC1新 dtb 没进 boot.img（只跑了 dts 没跑 bootimg），或没重新 pack、没刷机补 ./build.sh bootimg ＋ ./build.sh pack，用 §7 的 boot.img 计数自检（应为 2）
ttySAC1 有了但收不到数据① 引脚选错（PD21/PD22 vs PE10/PE11，按原理图）；② 波特率不是 9600；③ PD22 仍被背光 PWM7 占用核对 §3.4 的三组可选脚位；跑 dmesg | grep -i 'pin\|ttySAC' 看 pin 冲突；确认 &pwm7 已 disabled
编译报 build dts failed / dtc 报错dts 语法被改坏先跑 §5 的 cpp ＋ dtc 自检定位；再 diff -u 比对备份
