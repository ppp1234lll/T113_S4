TQT113 镜像主机名 / 账号 / 密码修改操作手册

天嵌 TQT113 / T113-S4 · Tina Linux SDK（linux-5.4 + Buildroot 201902）· 2026-10-16 · 本手册直接以 HTML 形态维护（无 .md 母本）
全文命令一条一行、各自独立可执行，一律绝对路径、不使用 shell 变量； 来源标记 【SDK】＝SDK 自带配置 / 脚本（附文件与行号），【补充】＝本手册自加的取证与防错步骤。 天嵌官方手册未收录本主题（已查证），故不标【官方】，见 §6。

这份手册改镜像里的三类东西，但只有一条主线：改 overlay 里的文件 → 重建 rootfs → 打包 → 刷机。 ① 主机名（串口提示符 root@TQ113:/# 里那个 TQ113，§2.1）； ② 账号名（默认 root，§2.2）；③ 密码（默认 embedsky，§2.2）。 三个都改，收尾也只是同一步（§2.3）。

2. 改法

2.1 改主机名：TQ113 → t113（4 条命令）

改完提示符就是 root@t113:/#。

① 先备份

cp -a /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/hostname /tmp/hostname.bak-1016; cp -a /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/hosts /tmp/hosts.bak-1016

② 改 hostname（这就是提示符里显示的那个名字）

sed -i 's|TQ113|t113|' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/hostname

③ 改 hosts（保持与主机名一致，免得本地解析对不上）

sed -i 's|TQ113|t113|' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/hosts

2.2 改账号 / 密码：账号 root → t113，密码 → 123456（6 条命令）

这一节是可选的 —— 只想改主机名就跳到 §2.3。要换成别的账号名或密码，只改下面出现的 t113 与 123456（通用写法见 §3）。

① 先备份

cp -a /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/passwd /tmp/passwd.bak-1016; cp -a /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow /tmp/shadow.bak-1016

② 把账号名 root 改成 t113 —— passwd 与 shadow 两处都要执行，只改一处会登录不上

sed -i 's|^root:|t113:|' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/passwd
sed -i 's|^root:|t113:|' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow

③ 把密码改成 123456 —— t113salt 是盐（可自定、8 位即可），密码用单引号包住

sed -i "s|^t113:[^:]*:|t113:$(openssl passwd -1 -salt t113salt '123456'):|" /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow

④ 核对 —— 下面两行是实测真实输出

grep '^t113:' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/passwd /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow
.../rootfs_overlay/etc/passwd:t113:x:0:0:root:/root:/bin/sh
.../rootfs_overlay/etc/shadow:t113:$1$t113salt$BH93kyL/.APaEiPC8whDh/:1:0:99999:7:::

顺便确认 root 已不存在（两条都应输出 0）：

grep -c '^root:' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/passwd /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow

两个要知道的副作用（实测无碍）：① 改名后 root 这个账号就没了，板端 su（不带参数）会找不到 root，请用 su t113； ② passwd 里第 5 字段（描述）仍是 root、家目录仍是 /root —— 不影响功能，保留家目录反而最省事（不用建目录、不用改属主）。

为什么可以放心改名：已核对整个 overlay，凡出现 root 的地方全是注释与变量名 （log_root / server_root / udev_root / rootpath），没有 chown root / su root 这类按用户名操作； Buildroot 的 Makefile 里也没有任何 chown。所以构建与启动都不依赖 root 这个名字。

2.3 收尾：重建 rootfs ＋ 打包 ＋ 刷机（不管改了几处，都只做这一次）

cd /opt/Embedsky/mount/t113_tina
./build.sh
./build.sh pack

⚠ 必须用「无参」的 ./build.sh。下面三种跑法看着都像"重新编译"，但只有第一种能让改动进固件：

命令刷新 Buildroot 的 target/刷新打包输入 rootfs.ext4烧完能看到新名
./build.sh（无参）✅✅✅ 用这个
./build.sh buildroot_rootfs✅❌❌ 后面 pack 打进固件的是旧 rootfs
./build.sh kernel❌❌❌ 只编内核，完全不碰 rootfs

为什么：pack 本身不生成 rootfs，它只把 out/t113_s4/evb1_auto/buildroot/ 下现成的 rootfs.ext4 打进固件。 生成这枚 rootfs.ext4 的是 build/mkcmd.sh:2201 pack_buildroot_rootfs()（内部调 :2083 make_ext4()）； 而 pack_buildroot_rootfs() 只被 :2273 build_rootfs() 调用（:2295）， build_rootfs() 又只被 :2436 build_linuxdev() 调用（:2483）—— 而 build_linuxdev 正是无参 ./build.sh 的默认动作（build/mkcommon.sh:34 ACTION="build_linuxdev;"）。 反过来看 buildroot_rootfs：build/mkcommon.sh:70 把它直接派发给 build/mkcmd.sh:1304 build_buildroot_rootfs()， 整条链上都没有 pack_buildroot_rootfs —— 所以它只刷新 Buildroot 自己的 buildroot/buildroot/{target, images/rootfs.ext2}，不碰打包输入的 rootfs.ext4。

无参 ./build.sh ＝ 全量（bootloader ＋ kernel ＋ rootfs）；本机 1 核 VM 实测 8 分 27 秒跑完 ./build.sh ＋ ./build.sh pack（缓存已就绪；从零或大改会明显更久）。
嫌重也可以用官方一键脚本 ./auto_build.sh t113_s4 buildroot（内部已含 ./build.sh ＋ ./build.sh pack，跑完不用再 pack）， 代价是它会 rm -rf rootfs_overlay/opt 再重灌。

验证新值真进了镜像 —— 分两级看：

① Buildroot 自己的产物（跑完无参 ./build.sh 就该是 t113；但它对不对，不代表打包输入也对）：

debugfs -R "cat /etc/hostname" /opt/Embedsky/mount/t113_tina/out/t113_s4/evb1_auto/buildroot/buildroot/images/rootfs.ext2 2>/dev/null

② 打包输入 rootfs.ext4 与最终 .img —— 这两枚是稀疏 ext4／整盘镜像，debugfs 读不了（会报 Bad magic number）， 直接搜字符串最省事；能搜出 t113 才算真进去了：

grep -ao "127\.0\.1\.1[^0-9A-Za-z]\{1,4\}[A-Za-z0-9]\{3,8\}" /opt/Embedsky/mount/t113_tina/out/t113_s4/evb1_auto/buildroot/t113_s4_linux_evb1_auto_uart0.img
127.0.1.1	t113

再看一眼旧名还有没有残留（应为 0）：

grep -ac "TQ113" /opt/Embedsky/mount/t113_tina/out/t113_s4/evb1_auto/buildroot/t113_s4_linux_evb1_auto_uart0.img

刷机方式见《TQT113_linux_使用手册》§3.1.2 USB 原厂工具更新（Windows＝PhoenixSuit）或 §3.1.5 fastboot 更新 （具体命令以官方原文为准，本手册不复写）。刷完板端 hostname 应回 t113、提示符变成 root@t113:/#。 想在当前这颗板子上立即看到（不重启）：执行 hostname -F /etc/hostname，再新开一个 shell。

把 <ETC> 当作 §1 那个 overlay 的 etc 目录，把 <旧主机名>／<账号>／<旧名>／<新名>／<新密码>／<盐> 换成你的值。

要做什么命令
改主机名（两处都做）sed -i 's|<旧主机名>|<新主机名>|' <ETC>/hostname
和 sed -i 's|<旧主机名>|<新主机名>|' <ETC>/hosts
改账号密码（最常用）sed -i "s|^<账号>:[^:]*:|<账号>:$(openssl passwd -1 -salt <盐> '<新密码>'):|" <ETC>/shadow
改账号名（两处都做）sed -i 's|^<旧名>:|<新名>:|' <ETC>/passwd
和 sed -i 's|^<旧名>:|<新名>:|' <ETC>/shadow
新增账号<ETC>/passwd 与 <ETC>/shadow 各 echo '...' >> 一行（uid/gid 用没被占的，如 1001；shadow 第 3 字段写 19000 之类的历史日可免"密码过期"提示）
删账号sed -i '/^<账号>:/d' <ETC>/passwd
和 sed -i '/^<账号>:/d' <ETC>/shadow
核对grep -Hn . <ETC>/hostname <ETC>/hosts、grep '^<账号>:' <ETC>/passwd <ETC>/shadow

三个必须记住的点：

  1. 成对的文件要一起改 —— 主机名要同时改 hostname 与 hosts；账号名要同时改 passwd 与 shadow。只改一边会出问题（账号那条直接登录不上）。
  2. 哈希里有 $，手工粘贴时必须用单引号（或者像上表那样直接用 $(openssl ...) 生成）—— 放双引号里会被 shell 当成变量展开成空，写进去是条假哈希，表现就是"改完登录不上"；
  3. 改完一律是 ./build.sh buildroot_rootfs ＋ ./build.sh pack ＋ 刷机； ./build.sh kernel 不管 rootfs。

4. 排障速查

现象原因处理
改完刷机，提示符还是 root@TQ113最常见：只跑了 ./build.sh buildroot_rootfs —— 它不刷新打包输入的 rootfs.ext4（见 §2.3）；其次才是走了 ./build.sh kernel（压根不碰 rootfs）；再次是漏了 pack 或没刷机用无参 ./build.sh ＋ ./build.sh pack；先按 §2.3 ② 用 grep 确认 .img 里已是 t113、TQ113 计数为 0，再刷机
改了 rootfs_overlay 里的文件，每次烧完都是旧值打包输入 out/.../buildroot/rootfs.ext4 是陈旧的 —— 用 ls -la 对比：它比 out/.../buildroot/buildroot/target/ 旧，就说明 pack_buildroot_rootfs() 没跑过跑无参 ./build.sh（它会调 pack_buildroot_rootfs() 刷新 rootfs.ext4），再 ./build.sh pack
提示符名字对了，但别的程序还报旧名hosts 没跟着改补 sed -i 's|TQ113|t113|' <ETC>/hosts 再重编
改完登录不上哈希写坏：多半是在双引号里粘贴了带 $ 的哈希被 shell 展开用 §3 的 $(openssl ...) 写法；核对时确认哈希只由 [./0-9A-Za-z$] 组成、没有引号字符
debugfs 报 Bad magic number in super-block喂了 out/.../buildroot/rootfs.ext4（Android sparse image）改用 out/.../buildroot/buildroot/images/rootfs.ext2（1 GiB 裸 ext4）
grep 看不到改动改到了非编译用的那份文件确认路径是 board/embedsky/tqt113-s3/rootfs_overlay/etc/...（§1）
