3. 方案 A —— 改账号 / 密码（量产用）

3.0 照抄版：账号改成 t113、密码改成 123456（6 条命令）

按顺序粘贴即可。第 ② 步是"改账号名"、第 ③ 步是"改密码"；想换别的账号名或密码，只改这两步里出现的 t113 与 123456 即可（通用写法见 §6.1）。

① 先备份（改坏了能一条命令还原）

cp -a /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/passwd /tmp/passwd.bak-1016; cp -a /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow /tmp/shadow.bak-1016

② 把账号 root 改名为 t113 —— passwd 与 shadow 两处必须同时改，只改一处会登录不上

sed -i 's|^root:|t113:|' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/passwd
sed -i 's|^root:|t113:|' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow

③ 把密码改成 123456 —— t113salt 是盐（可自定、8 位即可）；密码与盐都用单引号包住

sed -i "s|^t113:[^:]*:|t113:$(openssl passwd -1 -salt t113salt '123456'):|" /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow

④ 核对 —— 应输出两行（下面就是本次实测的真实输出，可直接对照）

grep '^t113:' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/passwd /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow
.../rootfs_overlay/etc/passwd:t113:x:0:0:root:/root:/bin/sh
.../rootfs_overlay/etc/shadow:t113:$1$t113salt$BH93kyL/.APaEiPC8whDh/:1:0:99999:7:::

再补一条：确认 root 这个账号已经不存在了（两条都应输出 0）

grep -c '^root:' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/passwd /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow

⑤ 重建 rootfs ＋ 打包

cd /opt/Embedsky/mount/t113_tina
./build.sh buildroot_rootfs
./build.sh pack

⚠ ./build.sh kernel 不会重建 rootfs，用它等于白改（理由见 §3.5）。

⑥ 验证真进了镜像 ＋ 刷机

debugfs -R "cat /etc/shadow" /opt/Embedsky/mount/t113_tina/out/t113_s4/evb1_auto/buildroot/buildroot/images/rootfs.ext2 2>/dev/null | head -1

应看到 t113:$1$t113salt$BH93kyL/.APaEiPC8whDh/:1:0:99999:7::: 这一行。然后按 §3.7 刷机，板端执行 whoami 应回 t113。

还原（改坏了就这两条，再按 ⑤ 重编）

cp -a /tmp/passwd.bak-1016 /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/passwd; cp -a /tmp/shadow.bak-1016 /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow

两个要知道的副作用（实测确认无碍）：① 改名后 root 这个账号就没了，以后板端 su（不带参数）会找不到 root， 请用 su t113；② /etc/passwd 里第 5 字段（描述）仍是 root、家目录仍是 /root——不影响功能，保留家目录反而最省事（不用建目录、不用改属主）。 若确实想连描述一起改，把 ② 的第一条换成 sed -i 's|^root:x:0:0:root:|t113:x:0:0:t113:|' <path>/etc/passwd。

为什么可以放心改名：已核对整个 overlay，凡出现 root 的地方全是注释与变量名（log_root / server_root / udev_root / rootpath）， 没有一处是 chown root / su root 这类按用户名操作；Buildroot 的 Makefile 里也没有任何 chown。所以构建与启动都不依赖 root 这个名字。

3.1 生成新密码的哈希（1 条命令）

先用 openssl 算 MD5-crypt 哈希。把 YourNewPass 换成你要的密码（引号用单引号，避免 shell 展开）：

openssl passwd -1 -salt 'tq2026salt' 'YourNewPass'

输出形如 $1$tq2026salt$57uMh.BHiZS5Vvr42vr6i1 —— 这就是要写进 shadow 第二个字段的东西。 盐（这里是 tq2026salt）可自定，8 位左右、别带引号和 $。

想用随机盐（每台不同、更安全）就换成下面这条，它把盐交给 openssl rand：

openssl passwd -1 -salt "$(openssl rand -hex 4 | cut -c1-8)" 'YourNewPass'

3.2 写回 shadow（1 条命令，已实测）

推荐这条：生成 ＋ 写入一步完成，不经过"手工复制哈希"这一步（避开 §3.4 的坑）：

H=$(openssl passwd -1 -salt "$(openssl rand -hex 4 | cut -c1-8)" 'YourNewPass'); sed -i "s|^root:[^:]*:|root:${H}:|" /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow

它只替换 root 行的第 2 个字段（^root:[^:]*: → root:<新哈希>:），后面的 :1:0:99999:7:::（上次修改 / 最短 / 最长 / 告警 / 失效）原样保留，不会动其它账号。

若你已完成 3.1 拿到哈希、想手工粘回去，这条命令的哈希必须放在单引号里：

sed -i 's|^root:[^:]*:|root:$1$tq2026salt$57uMh.BHiZS5Vvr42vr6i1:|' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow

⚠ 为什么必须单引号：哈希里有 $1、$tq2026salt 这种片段，放进双引号里会被 shell 当成变量展开成空串， 结果写进去一条没有密码字段的假哈希 —— 表现就是"改完登录不上"。

3.3 核对（1 条命令）

grep '^root:' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow

期望：一行 root:$1$<你的盐>$<哈希>:1:0:99999:7:::，哈希里不能出现引号字符（见 §3.4 的实测失败案例）。

3.4 ⚠ 三个实测坑（都真跑过，别踩）

写法结果说明
sed -i "s|^root:[^:]*:|root:$(openssl passwd -1 -salt tqtest01 "NewPass123"):|" ...（固定盐、命令替换）✅ 正确写入 root:$1$tqtest01$57uMh.BHiZS5Vvr42vr6i1:1:0:99999:7:::，与 openssl 输出完全一致
sed -i "s|...|root:$(openssl passwd -1 -salt \"$(openssl rand -hex 4|cut -c1-8)\" "NewPass123"):|" ...（双引号里嵌套 \"...\"）❌ 写坏结果是 root:$1$"af59ccb$znoZU2gyyATsvux3kkhqo.:... —— 盐里混进了一个双引号，哈希无效，改完会登录不上
H=$(...); sed -i "s|^root:[^:]*:|root:${H}:|" ...（变量 ＋ 随机盐，无嵌套引号）✅ 正确写入 root:$1$bd7b3fc0$yC5y0TPKua4DqEItuPPaO1:...；用盐 bd7b3fc0 反算得 $1$bd7b3fc0$yC5y0TPKua4DqEItuPPaO1，吻合；grep -c '"' ＝ 0

所以规则很简单：不要把 \"...\" 套在双引号里做嵌套；要么用固定盐（无嵌套），要么用 §3.2 的变量写法（一条命令、; 连接）。

3.5 重建 rootfs 并打包

⚠ 关键：./build.sh kernel 不会重建 rootfs！ 它只编内核＋设备树＋boot.img（见《UART1 设备树启用操作手册》§6）；而 etc/shadow 属于 rootfs， 必须走重建 rootfs 的 target，否则你改了 shadow、刷进去的还是老密码。

首选（范围最小，只重建 rootfs）：

cd /opt/Embedsky/mount/t113_tina
./build.sh buildroot_rootfs
./build.sh pack

保底（全量，最不容易漏东西）：

cd /opt/Embedsky/mount/t113_tina
./build.sh
./build.sh pack
命令干什么来源
./build.sh buildroot_rootfs重建 rootfs：跑 Buildroot 构建（overlay 会被重新 rsync 进 target/）＋ 从 device/ 拷配置文件【SDK】build/mkcommon.sh:70 分派 → build/mkcmd.sh:1304 build_buildroot_rootfs()
./build.sh（不带参数）全量构建：内核 ＋ 设备树 ＋ rootfs ＋ boot.img。auto_build.sh 内部用的就是它【SDK】auto_build.sh 第 15 行
./build.sh pack按分区表把 out/ 里的现成件打成整包固件【SDK】auto_build.sh 第 16 行

要刷的镜像：/opt/Embedsky/mount/t113_tina/out/t113_s4/evb1_auto/buildroot/t113_s4_linux_evb1_auto_uart0.img。

3.6 验证"新密码真的进了镜像"（3 条命令，逐级加深）

第一级 —— 看构建产物（重建 rootfs 后立刻可查）：

grep '^root:' /opt/Embedsky/mount/t113_tina/out/t113_s4/evb1_auto/buildroot/buildroot/target/etc/shadow

第二级 —— 看裸 rootfs 镜像里真正烧进去的那份（pack 前后都可）：

debugfs -R "cat /etc/shadow" /opt/Embedsky/mount/t113_tina/out/t113_s4/evb1_auto/buildroot/buildroot/images/rootfs.ext2 2>/dev/null | head -1

第三级 —— 反算校验：把哈希里的盐取出来重算一遍，确认它确实对应你的明文密码：

openssl passwd -1 -salt 'tq2026salt' 'YourNewPass'

三级的输出应当一致（第二级要等 rootfs.ext2 重新生成，即 mtime 更新之后）。

4. 方案 B —— 板端现场改（单台、不重编）

因为 rootfs 是可写的（inittab 里有 mount -o remount,rw /），板端直接改就能存住（reboot 后仍在）：

passwd

按提示输入两次新密码即可（busybox 的 passwd，当前是 root 身份所以改的就是 root 的密码）。

确认：

grep '^root:' /etc/shadow

局限（为什么量产不用它）：

  • 逐台操作，一批板子改不完；
  • 一旦重新刷机 / 恢复出厂 / 走 OTA 覆盖 rootfs，改动就丢了；
  • 若将来把根文件系统改成只读（squashfs / overlayfs+只读底层），这条路会失效。

5. 方案 C —— 让串口也要求输账号密码（改 inittab）

出厂 inittab 第 37 行是：

::respawn:-/bin/sh

开头那个 - 就是"当作 login shell 但不要求登录"，所以串口直接是 root。想改成"要登录"，把它换成 getty：

sed -i 's|^::respawn:-/bin/sh$|::respawn:/sbin/getty -L 115200 console vt100|' /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/inittab

核对：

tail -3 /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/inittab

然后按 §3.5 重建 rootfs ＋ pack ＋ 刷机。这样做必须先在 §3 里有一个你自己知道的密码，否则串口就进不去了。

⚠ 本条未在本板实测（板子当前不在网）。两个注意点：① 该行 id 字段为空 ⇒ 跑在 /dev/console 上， 若 console 这个名字 getty 不认，改成官方注释里留的那个写法 —— ::respawn:/sbin/getty -L ttyS0 115200 vt100 （inittab 第 36 行注释里就是这条）；② 改错会导致串口完全没有 shell，务必先用 §3/§4 确认另一个能进的入口，或保留一份原文件备份：

cp -a /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/inittab /tmp/inittab.bak-1016

6. 方案 D —— 新增一个普通账号

这个镜像里没有 useradd（busybox 未编入），所以直接往 overlay 的 passwd / shadow 里各加一行：

echo 'ivsuser:x:1001:1001::/home/ivsuser:/bin/sh' >> /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/passwd
openssl passwd -1 -salt 't113salt' 'YourNewPass'
echo 'ivsuser:$1$t113salt$BH93kyL/.APaEiPC8whDh:19000:0:99999:7:::' >> /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow

（上面那串哈希对应的明文是 123456、盐 t113salt，是 openssl 实测值；换成你自己的密码就用上一条命令重新生成、替换掉中间那段。） 再建家目录，然后按 §3.5 重建 rootfs ＋ pack ＋ 刷机：

mkdir -p /opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/home/ivsuser

⚠ 本条未在本板实测。注意：① uid/gid 不要和现有账号撞（现有最大是 65534 nobody，1001 可用）； ② shadow 第 3 个字段是"上次修改日"，写 19000 这类历史日期可避免"密码过期"提示，也可留空； ③ 用 >> 追加会重复，先 grep '^ivsuser:' 确认没有再加。

6.1 通用模板：以后改任意账号，都照这张表来

下面用 <ETC> 指代 §1 里那个 overlay 的 etc 目录 （/opt/Embedsky/mount/t113_tina/buildroot/buildroot-201902/board/embedsky/tqt113-s3/rootfs_overlay/etc）。 把 <账号>／<旧名>／<新名>／<新密码>／<盐> 换成你的值即可。

要做什么命令
改密码（最常用）sed -i "s|^<账号>:[^:]*:|<账号>:$(openssl passwd -1 -salt <盐> '<新密码>'):|" <ETC>/shadow
改账号名（两处都要做）sed -i 's|^<旧名>:|<新名>:|' <ETC>/passwd
和 sed -i 's|^<旧名>:|<新名>:|' <ETC>/shadow
新增账号passwd／shadow 各 echo '...' >> 一行（见 §6）
删账号sed -i '/^<账号>:/d' <ETC>/passwd
和 sed -i '/^<账号>:/d' <ETC>/shadow
核对grep '^<账号>:' <ETC>/passwd <ETC>/shadow
改完后（每次都一样）cd /opt/Embedsky/mount/t113_tina → ./build.sh buildroot_rootfs → ./build.sh pack → 刷机

三个必须记住的点：

  1. passwd 与 shadow 要一起改 —— 账号名两边都写了，只改一边就登录不上。
  2. 哈希里有 $，手工粘贴时必须用单引号（或像上表那样直接用 $(openssl ...) 生成）， 在双引号里会被 shell 当成变量展开成空，写进去是条假哈希。
  3. 改完必须重建 rootfs（./build.sh buildroot_rootfs，或全量 ./build.sh）＋ pack； ./build.sh kernel 不管 rootfs。

7. 排障速查

现象原因处理
改了 shadow、刷完还是老密码走了 ./build.sh kernel —— 它不重建 rootfs；或漏了 pack / 没刷机改用 §3.5 的 ./build.sh buildroot_rootfs（或全量 ./build.sh）＋ pack
改完登录不上了哈希写坏：典型是在双引号里粘贴了带 $ 的哈希，被 shell 展开；或 §3.4 的嵌套引号把 " 吃进盐用 §3.2 的变量写法或 §3.3 核对；确认哈希里只有 [./0-9A-Za-z] 与 $
改完串口进不去了§5 的 getty 配置不生效 / tty 名不对用备份 cp -a /tmp/inittab.bak-1016 <overlay>/etc/inittab 还原后重编；或先确认 console 换成 ttyS0
debugfs 报 Bad magic number in super-block喂了 out/.../buildroot/rootfs.ext4（Android sparse image）改用 out/.../buildroot/buildroot/images/rootfs.ext2（1 GiB 裸 ext4）
板端 passwd 改完，重启又回去了rootfs 被挂成只读，或改动没写回分区确认 inittab 里仍是 mount -o remount,rw /；否则只能走 §3 改镜像
grep '^root:' 看不到改动改到了非编译用的那份文件确认路径是 board/embedsky/tqt113-s3/rootfs_overlay/etc/shadow（§1）
