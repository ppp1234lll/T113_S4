# 运维箱远程访问 · 一步一步用起来

> 适用：「运维箱远程访问.exe」1.1.2 及以上（`--selftest` 退出码 0 即全部自检通过）
> 交付物在 `delivery-1.0.0/tools/运维箱远程访问/`（其中 `一步一步使用说明.md` 即本文件）。
> 设备侧令牌/frpc 原理见 `远程通道使用说明.md`；本文件只讲**怎么点**。

---

## 先把三个角色分清楚

| 角色 | 是什么 | 谁来配 |
|---|---|---|
| **设备**（现场那台箱子） | 有 SN（身份证）；它**主动**去连服务器，把自己挂上去 | 设备 Web →「远程通道」 |
| **frps 服务器** | 公网上的中转，例如 `47.95.22.96:7000`，有一串 `auth.token` | 管理员（已经在跑的就不用管） |
| **本程序**（exe） | 在运维 PC 上，也去连同一台服务器，**点名**要哪个 SN | 「服务器设置」＋ 设备 SN 下拉框 |

一句话记住关系：**设备把 SN 挂到服务器上，你点名同一个 SN，服务器就把你俩接起来。**
所以「exe 连不上」九成不是 exe 的问题，而是**设备没挂上去**。

---

## 第 0 步：前提（缺一条都白搭）

1. **服务器已经跑着**，且知道「地址:端口」和那串令牌（frps 的 `auth.token`）。
2. **设备能上网**（4G 或网线都行），且知道它的 SN（设备 Web 首页显示，或看设备标签）。
3. **设备上装过本程序的公钥与三个脚本**：出厂镜像自带；老设备按交付目录 `DEPLOY.txt` 补一次
   （`/root/.ssh/authorized_keys` 里要有一行 `ssh-ed25519 ... ivremote-exe`，
   以及 `/opt/ivsbox/scripts/` 下的 `cams.py`、`checkcam.py`、`camstat.py`）。

> 确认设备能连到服务器，在设备上跑一句就够：
> `python3 -c "import socket;s=socket.socket();s.settimeout(6);s.connect(('47.95.22.96',7000));print('OK')"`
> 打 `OK` 说明 4G/网络到服务器这段是通的；打 `Timeout` 就是网络或防火墙问题，先解决这个。

---

## 第 1 步：让设备把通道挂到服务器（同一台设备只做一次）

1. 浏览器打开设备 Web（`http://设备IP`），登录。
2. 左侧菜单点 **「远程通道」**。
3. 填三项：
   - **服务器地址**：`47.95.22.96`
   - **端口**：`7000`
   - **令牌**：和 frps 完全一致的那串
4. **有效期**：选「长期」或按需的小时数。
5. 勾 **「开启通道」** → 点 **保存**（保存即生效，**不用重启设备**）。
6. 看页面顶部状态卡：**通道 = 已开启**、**frpc = 运行中**，并显示本机 SN。

**成功标志**（设备上 `tail /mnt/UDISK/log/frpc.log`，三行依次出现）：

```
login to server success
proxy added: [0A19B4]        ← 这行里的名字必须是你的 SN
[0A19B4] start proxy success
```

缺哪一行，对应的问题见文末「卡住了？」。

---

## 第 2 步：校准 exe 的服务器与令牌

> **1.1.3 起这一步通常可以跳过**：exe 出厂已内嵌 `47.95.22.96:7000`、当前令牌和默认
> SN=`0A19B4`，第一次双击打开就带着这些，直接去第 3 步即可。
> 只有下面两种情况才需要回到这一步：**换了 frps**、或**令牌被轮换过**（轮换后旧 exe
> 里内嵌的令牌就作废了，现象是 `token in login doesn't match token from configuration`）。

1. 打开 `运维箱远程访问.exe`。
2. 点 **「服务器设置」**。
3. 填和第 1 步**同一台** frps 的地址、端口、令牌 → **保存**。
4. 顶部右侧应显示 `服务器 47.95.22.96:7000`。

> **令牌三处必须同值**：服务器 frps 的 `auth.token`、设备「远程通道」页填的那串、这里的。
> 任何一处不同，现象都是 `token in login doesn't match token from configuration`（frpc 原话，
> 意思是**服务器说"你这令牌不是我配的那个"**）。改令牌是全局动作，三处必须一起改：
> 只改设备 + exe、没改服务器，就变成两边都登不上（2026-11-05 早上现场踩过）。

---

## 第 3 步：选设备 SN

1. 顶部 **设备 SN** 下拉框：选设备 SN；没在列表里就直接敲进去。
2. 选中即切换；手输的话点一下 **「切换」**。
3. 日志出现：`已切换到设备 SN=0A19B4（secretKey 已按新 SN 重算）`，
   状态条变成 `当前设备 0A19B4（服务器 47.95.22.96:7000）`。

> `secretKey` 由程序按「SN + 令牌」现算，**不需要你填，也不要在别处算**。
> 一台电脑管 N 台设备，就是在这里换 SN —— 不用重新打包、不用改配置文件。

---

## 第 4 步：刷新，看摄像机列表

点 **「刷新」**。

**成功**：列表出现设备上**真配了 IP** 的每一路，状态「可连接」，
本地地址从 `http://127.0.0.1:9090` 开始排。

**列表是空的**，看状态条末尾那句话，只有两种：

| 状态条末尾 | 含义 | 去查 |
|---|---|---|
| `读不到设备配置（见日志）` | 没连上设备 | 第 1 步没成（设备没挂上）、第 2 步地址/令牌不对、或第 3 步 SN 选错 |
| `设备未配摄像机 IP` | 连上了，但一路 IP 都没填 | 设备 Web →「摄像机」页填 IP 后回来刷新 |

日志里还有三条现成的排查提示，照着查即可。**程序不会拿假数据凑数**：
显示几路，就是设备上真配了几路。

---

## 第 5 步：开始用

| 按钮 | 干什么 |
|---|---|
| **连接并打开** | 建一条到某一路摄像机的隧道，并自动打开浏览器（选中一行再点，或直接双击那一行） |
| **设备 Web** | 打开设备本机管理页面（本地 `18080`） |
| **下载文件** | 打开 SD 卡文件浏览器：双击文件即下载，Ctrl 多选可批量；「保存到」可改目录 |
| **断开** | 拆掉当前隧道（frpc 保留，下次连更快） |
| **刷新** | 重新读摄像机列表并重新探测 |

> 隧道里走的是 ssh，**看画面和下载文件不要同时做**，两者抢同一条上行。

## 卡住了？三句话定位

按顺序看两个日志：

- 设备上：`/mnt/UDISK/log/frpc.log`（也可用设备 Web「远程通道」页看状态）
- 电脑上：`%LOCALAPPDATA%\ivsbox-remote\frpc.log` 和 `run.log`

| 现象 | 说明 |
|---|---|
| `token in login doesn't match token from configuration` | **令牌三方不一致**：设备/exe 改了、服务器 frps 没改（或反之）。地址端口是通的，别去查网络 |
| `login to server failed`（其它原因） | 地址 / 端口不通，或服务器没起 |
| login 成功，但**没有** `start proxy success` | 服务器拒绝了这台设备注册（SN 重复，或该 SN 不被允许） |
| 设备侧有 `start proxy success`，电脑侧**没有** `start visitor success` | 电脑连的服务器和设备的**不是同一台**，或端口填错 |
| ssh 报 `kex_exchange_identification` | SN 名字对上了但钥匙不匹配（令牌不一致），或设备没装本程序公钥 |

一条命令跑完整自检（不弹界面，结果写进 `run.log`，退出码 0 = 全通过）：

```
运维箱远程访问.exe --sn 0A19B4 --selftest
```

反向证伪：故意填一个设备上不存在的 SN（如 `--sn 0B2CC1`），
若自检里的「ssh 免密登录设备」变 FAIL，说明 SN 确实是**真的**参与连路，而不是摆设。

## 实测数据（板 `192.168.1.64`，SN `0A19B4`，经公网 `47.95.22.96:7000`）

| 项目 | 结果 |
|---|---|
| 摄像机列表 | **2 路**（`192.168.1.200` / `192.168.1.106`），均「可连接」 |
| 摄像机 Web | 隧道 `http://127.0.0.1:9090` 首页 `code=200` |
| SD 卡列目录 | 17 项 |
| 小文件（145 KB） | 约 7 秒 |
| 大文件（30 MB 录像） | 公网 + 4G 只有约 **14 KB/s**，107 秒只走到 1.4 MB 就断了 |

> **结论**：公网 + 4G 的链路很窄，先拿小文件验证通不通；
> 要批量拷录像，尽量在设备同一网段做（同一套 exe，把服务器指向局域网 frps 即可，
> 实测能到 1.3 MB/s）。大文件续传能力目前**没有**，见 `代码说明.adoc` 对应条目。

## 附：一次管很多台设备

1. 每台设备按第 1 步各配一次（同一个 frps、同一个令牌）。
2. 在 exe 同目录放一个 `sns.txt`，一行一个 SN（`#` 开头是注释，SN 后面可以跟备注）：

```
# 现场设备
0A19B4
0B2CC1    3号箱
```

3. 下次启动，这些 SN 就都在下拉框里，**选谁连谁**。
