# 运维箱通道配置 · 操作声明

> 工具：`ivsbox/tools/tunnelcfg/运维箱通道配置.exe` —— 编译版单文件，双击即开，
> 　　　**不依赖 PowerShell / python / .NET**；旧版 `tunnelcfg.ps1` 同语义保留，仅作对照
> 版本 1.1i　　2026-11-05（1.0 打开是空白界面，1.1 修复；同日出编译版 exe，见文末「版本」）
> 适用设备：ivsbox 运维箱（`/api/tunnel*` 可用，即 `ivsbox-web` 为带 tunnel 路由的版本）
> 交付副本：`delivery-1.0.0/tools/运维箱通道配置/`

---

## 0. 一句话说清这个工具存在的理由

通道能连上，取决于**三处用的是同一串令牌**：

| 位置 | 谁在用它 | 在哪 |
|---|---|---|
| **服务器 frps** | 设备与本机都要向它登录 | `/etc/frp/frps.toml` 的 `auth.token`（以及 `visitor.toml` 的） |
| **设备** | 设备自己拉起 frpc 去连服务器 | `/mnt/UDISK/ivsbox/secure/tunnel.token` → 渲染进 `/etc/frp/frpc.toml` |
| **本机 exe** | 你的电脑用同一串算 `secretKey` | `%LOCALAPPDATA%\ivsbox-remote\remote.ini` 的 `token=` |

**任一处不同 = 两边都登不上**，而且 frpc 只回一句
`token in login doesn't match token from configuration`，不看日志根本不知道是令牌问题。
本工具就是把这三点放到一个界面上，并且**每个动作都写明改了什么、什么时候生效、影响谁**。

## 1. 总表：点一下会发生什么

| 我点的按钮 | 改了什么（真实动作） | 何时生效 | 影响谁 |
|---|---|---|---|
| **一致性检查** | **什么都不改**，只读 | 立刻 | 无 |
| **生成新令牌** | 在输入框里生成 32 位 hex，**不写任何文件** | 只在界面上 | 无 |
| **下发令牌到设备** | `POST /api/tunnel/config` → 设备重写 `secure/tunnel.token` + `frpc.toml`；**不改开关**：原来开着就重开（换钥匙必须重连），原来关着就仍关着 | 设备 `monitor.sh` 下一轮（≤5 s） | **只有这一台设备**；若原来开着，通道闪断数秒 |
| **写入本机配置** | 改 `remote.ini` 的 `token=` 一行 | **重开 exe 时** | 只有本机 |
| **开通道 / 关通道** | `POST /api/tunnel/enable` / `/disable` | 立刻 | 只有这一台设备 |
| **复制服务器命令** | 只写剪贴板，**不执行** | —— | 无 |
| **一键轮换（三处同改）** | 依次：服务器 → 设备 → 本机；任一步失败即停 | 每步各自生效 | **该 frps 上所有设备**（先全断，再逐台恢复） |
| **保存日志** | 把输出区写成 txt | 立刻 | 无 |

## 2. 界面分区

### 2.0 第一次打开，按这三步点（界面下方也印着）

1. **先点「一致性检查」** —— 只读，不改任何东西。它会回答"三处是不是同一串令牌"，
   并告诉你本机 16000 在不在监听（在监听＝本机 frpc 已经登录成功）。
2. **要换令牌**：点「生成新令牌」→ 按提示点「下发令牌到设备」，再点「写入本机配置」。
   要让服务器也一起换：在「SSH 口令」里填服务器口令，点「一键轮换（三处同改）」。
3. **改完关掉并重开「运维箱远程访问.exe」**，点「刷新」。

> 令牌框是密码样式（显示为圆点），里面装的是**真实令牌**，不是占位符。
> 点「生成新令牌」或「一致性检查」的输出里都能看到它的前后几位。

```
① 服务器（frps）   地址 / 端口 / 令牌            [生成新令牌] [复制服务器命令]
                   SSH 口令（只用于改 frps，不落盘）
② 设备（ivsbox）   设备 IP / 账号 / 口令
③ 本机             配置文件路径（remote.ini）
④ 操作             一致性检查  下发令牌到设备  写入本机配置  开通道  关通道
                   一键轮换（三处同改）  保存日志  清空
   输出区          每一步的 [OK]/[X]/[WARN] 与结论
```

**所有改真实文件/接口的按钮都会先弹一次确认框**，框里写明"要改哪里、会闪断多久"。

## 3. 逐项操作声明

### 3.1 一致性检查（`-Action check`）

- **前置**：设备 IP 可达、设备 Web 账号口令正确；本机 exe 至少跑过一次（生成 `remote.ini`）。
- **动作**：只读三处，不写任何东西。读 `remote.ini`、`GET /api/tunnel`、探测本机 `127.0.0.1:16000`。
- **判据**：
  - 本机令牌长度 vs 设备 `token_len` —— **只能比长度**，设备按设计不回令牌明文（`token_set/token_len` 只有这两个字段）。
  - 服务器地址：`remote.ini` 的 `host` vs 设备报的 `server`。
  - **真正的"三处同值"证据是本机 16000 在监听**：那说明本机 frpc 已经向 frps 登录成功。
- **局限（必须知道）**：设备与 frps 之间是否登录成功，本工具**不直接验证**（要看设备日志或看设备 Web 状态）；工具给的是"本机侧是否真的通了"。

### 3.2 生成新令牌

- **动作**：`RandomNumberGenerator` 取 16 字节 → 32 位小写 hex，**只填进输入框**。
- **不做**：不写文件、不发请求。
- 合规字符：`0-9 A-Z a-z - _ . ~ + / = @`，长度 1~63（设备侧白名单，超了会被拒）。

### 3.3 下发令牌到设备（`-Action device-token -Token ...`）

- **前置**：设备 Web 账号口令正确；知道要下发哪一台（IP）。
- **动作**：`POST /api/tunnel/config {"token":..., "ttl":0, "enable":true}`
  - 设备侧落盘 `secure/tunnel.token`（0600），重写 `/etc/frp/frpc.toml`；
  - `monitor.sh` 在下一轮（≤5 s）按标记文件拉起 frpc，**secretKey 自动按「新 SN＋新令牌」重算**；
  - 工具在 6 秒后复查一次 `token_set`。
- **影响范围**：**只有这一台设备**；同一台 frps 上的其它设备不受影响。通道会闪断数秒。
- **失败会怎样**：接口非 0 或复查失败 → 输出 `[X]`，工具**不会**去动本机配置，避免出现"两边不同值"。
- **回滚**：再下发一次旧令牌即可（工具不需要额外状态）。

### 3.4 写入本机配置（`-Action ini-token`）

- **前置**：`remote.ini` 已存在（exe 跑过一次才生成）。
- **动作**：只替换 `token=` 这一行，其余行（host/port/sn/设备列表）原样保留，UTF-8/ASCII 写回。
- **生效**：**必须关掉再重开 exe**（程序启动时读 ini，运行中不重读）。
- **回滚**：把旧值写回去；或删掉 `remote.ini` 让 exe 回落到内置默认令牌（默认值不一定是当前 frps 的值，慎用）。

### 3.5 开通道 / 关通道（`-Action dev-on` / `dev-off`）

- **动作**：`POST /api/tunnel/enable|disable`。
- **关通道 = 设备侧 frpc 被停、标记文件清掉**：设备立刻从 frps 消失，本机 exe 随之连不上。**这是"断网"级别的操作**，只在排查或停用设备时用。
- **回滚**：再点开通道。

### 3.6 改服务器令牌（两种方式，都不需要你手改配置文件）

- **A. 自动（推荐，需要 SSH 口令）**：工具用 `plink` 登录 `EcsHost`，执行：
  ```sh
  cp -a /etc/frp/frps.toml   /etc/frp/frps.toml.bak-<时间戳>
  cp -a /etc/frp/visitor.toml /etc/frp/visitor.toml.bak-<时间戳>
  sed -i 's|^auth\.token = ".*"|auth.token = "<新令牌>"|' /etc/frp/frps.toml /etc/frp/visitor.toml
  sed -i 's|^webServer\.password = ".*"|webServer.password = "<新令牌>"|' /etc/frp/frps.toml
  systemctl restart frps; systemctl restart frpv
  ```
  改完自动检查 7000 是否在听。**注意 `webServer.password` 也用的是这串令牌**（frps 面板口令），所以一并改；**`visitor.toml` 必须一起改**，否则访问端 `frpv`（8080/18081 那套）会掉。
- **B. 手工（没有 plink / 不想给口令）**：点「复制服务器命令」，到服务器上以 root 粘贴执行，效果完全相同。
- **影响范围：该 frps 上所有设备一起失效**，直到每台设备各自下发新令牌。**这是本工具里最"重"的操作。**
- **回滚**：备份文件就在同目录，`cp /etc/frp/frps.toml.bak-<时间戳> /etc/frp/frps.toml && systemctl restart frps`。

### 3.7 一键轮换（`-Action rotate`）

- **顺序固定：服务器 → 设备 → 本机。** 理由：先让服务器认新值，再把设备对齐，最后改本机；
  任何一步失败**立即停**并报告"现在三处分别是什么值"，不会留下"设备改了、本机没改"这种更难查的中间态。
- **前置**：SSH 口令（或私钥）；设备 Web 口令；exe 已关或可重开。
- **收尾提示**：重开 exe → 刷新。**别的设备各自下发一次**。

### 3.8 保存日志

把输出区原样存成 txt，给远程支持用。**日志里的令牌是掩码**（`6a8f…c3 (len=32)`），
唯一的例外是点了「生成新令牌」后的那行——那是**故意明文**，方便你抄到别处。

## 4. 命令行（无人值守 / 批量）

```powershell
# 只读检查（CI 或远程巡检）
.\tunnelcfg.ps1 -NoGui -Action check -DevicePass <设备口令>

# 只给某台设备换令牌
.\tunnelcfg.ps1 -NoGui -Action device-token -Token <32位> -DeviceIp 192.168.1.64 -DevicePass <口令>

# 全量轮换（令牌不填则自动生成）
.\tunnelcfg.ps1 -NoGui -Action rotate -DevicePass <口令> -EcsPass <SSH口令>
```

动作取值：`read` / `check` / `rotate` / `device-token` / `ini-token` / `ecs-token` / `dev-on` / `dev-off`。
**退出码 0 = 全部成功，1 = 有失败**（失败行以 `[X]` 开头），可直接接脚本判断。
设备口令也可用环境变量 `IVSBOX_WEB_PASS` 传入，避免出现在命令行历史里。

## 5. 安全与数据

- **口令只在内存**：SSH 口令、设备口令都不写文件、不打日志；脚本参数走 `-EcsPass`/`-DevicePass` 或环境变量。
- **工具本身不含任何令牌/密钥**，所以它可以进仓库、可以发给别人。
- **服务器指纹固定在校验位**：`ssh-ed25519 255 SHA256:Uy99qmPWoPgHefIFj1Am23sr0QVoC8RnpS43+ENUID4`。
  指纹变了说明服务器重装或被顶替，工具会直接拒绝执行（需显式 `-EcsHostKey` 覆盖）。
- 备份策略：服务器侧每次改都留 `*.bak-<时间戳>`；设备侧旧令牌不保留（按设计只存当前值）。

---

## 6. 已知限制

1. **拿不到设备当前令牌明文**（设备侧有意不回），所以只能比长度 + 看本机 16000 是否通。
2. **自动改服务器依赖 plink.exe**（`C:\Program Files\PuTTY\plink.exe`）；没有就用「复制命令」。
3. **一次只处理一台设备**；多台要逐台执行 `device-token`。
4. **本机 16000 若被别的进程占用**，检查结果会误报"已通"——此时看 exe 日志确认。
5. 设备 Web 账号口令变更后，工具不会自动跟随，需在界面上改。

## 7. 出问题怎么退回去

| 症状 | 退法 |
|---|---|
| 改完服务器，所有设备都掉 | `cp /etc/frp/frps.toml.bak-<时间戳> /etc/frp/frps.toml && cp /etc/frp/visitor.toml.bak-<时间戳> /etc/frp/visitor.toml && systemctl restart frps frpv` |
| 只改了设备，本机没改 | 给本机「写入本机配置」同一个值，重开 exe |
| 只改了本机 | 给设备「下发令牌到设备」同一个值 |
| 通道关了忘记开 | 点「开通道」 |
| 不确定三处是什么值 | 点「一致性检查」，再对照本文件第 0 节的三处位置 |

## 8. 版本

### 1.1i（2026-11-05 17:05）409 不再装成"失败" ＋ 下发令牌不再顺手开门

- **`开关失败（HTTP 409）` 是误报**：409 就是设备的 `e=-7(IV_ESTATE)`＝"通道已经是你要的状态"，
  不是故障。现在遇到它，工具会**复查一次真实开关**，一致就报
  `[OK] 本来就是开着的（e=-7）—— 这次没有重复动作`；不一致才提示"再点一次"。
- 其他错误一律带上设备自己那句：`开关被拒（HTTP 403, e=-7）：must change password` ——
  不再只剩一个数字。
- **为什么第一下就 409**：原来的「下发令牌到设备」请求里写死 `enable:true`，
  而设备侧 `tunnel.configure` 收到它会把通道**开起来**。于是轮换/下发之后通道已经开着，
  紧跟着点「开通道」必然 409；反过来，本来关着的通道点一下"下发令牌"就自己开了。
  现在改为**先读当前开关再下发**，`enable` 跟着原状态走；读不到状态就中止，不猜。
- 验证（真机 1.64）：`开→关→关着时下发令牌→开→开着时下发令牌→再开` 六步全 OK，
  且关着时下发令牌后 `/tmp/frp.enabled` **没有**被创建（副作用消除）。
- 事故与修复一并登记：验证"同值下发"时误用了旧令牌，导致设备 frpc 报
  `token in login doesn't match token from configuration`；用 `remote.ini` 的**现值**重新下发后
  `login to server success`，三处恢复同值。**"同值"验证一律先读现值，别信文档里的历史令牌。**

### 1.1h（2026-11-05 16:52）把「一致性检查」的结论说准

- 原结论把"必要条件"当结论，而且举例的实测（本机 `16000` 监听）只证明 **本机↔frps**。
  现在按"能证明什么"分开写：令牌只进不出 ⇒ 本机证不了"值相同"；能当证据的只有登录结果，
  本机看 `16000`，设备侧只能等通道打开后看它的 frpc 有没有在 frps 上线。
- 设备 `on=false` 时补一句「设备 frpc 根本没启动，先点『开通道』才有登录结果可看」。
- 实测补充（本机 1.64，用 root SSH 读值）：设备 `secure/tunnel.token` 与本机
  `remote.ini` 的 `token` **逐字节相同**；服务器地址端口也一致。缺的只是"设备↔frps"
  这一段——因为通道关着，frpc 没起。
- 注意：`tunnel.status` 的 `opens/denies` 是**闸门**开关计数，不是 frpc 登录统计。

### 1.1g（2026-11-05 16:38）把「登录被拒」说清楚 ＋ 两个取证用的小口子

- **话术**：401 不再写"口令不对，**或该 IP 打不开**"（这两件事现场分不清），改成
  「账号或口令不对。出厂默认 `admin/88888888` 只在新机器上有效，这台可能已改过口令」。
  依据：`e=-23` 就是 `IV_EAUTH`，HTTP 401 是设备自己给的 ⇒ 网络是通的，问题在凭据。
- **「设备 IP」可写 `host:port`**：便于对着另一台机器上用临时口令文件起的实例
  （`ivsbox-web --port 18081 --pass-file …`）验一遍登录链路，默认仍是 80。
- **口令框不再 trim**：口令里若带首尾空格，原来会被悄悄抹掉，现象就是永远 401。
- **已知结论（本机 192.168.1.64）**：设备上 `secure/web.passwd` 的摘要与出厂口令
  `88888888` 对不上 ⇒ 这台箱子早就改过 Web 口令，请填真实口令；忘了可以重置（会改设备状态）。

### 1.1f（2026-11-05 16:22）修「点按钮没反应」

- **现象**：点「一致性检查」（以及其它八个动作按钮）界面上毫无反应，日志一行都不加。
- **真因**：按钮被创建成**分组框的子窗口**。Win32 里按钮的 `BN_CLICKED` 是
  `WM_COMMAND` 发给**父窗口**的，而分组框是 `STATIC` 类控件，`DefWindowProc` 把它丢掉
  ⇒ 主窗口收不到点击。WinForms 的 `GroupBox.Controls.Add()` 能这么写，Win32 的
  `BS_GROUPBOX` 只是画个框，不能当父窗口。
- **修法**：控件全部建在主窗口上、坐标加进分组框的位置（分组框仍是先建的兄弟窗口，
  不会遮控件）。界面与修前逐像素一致。
- **自检也一并修了**：`--shot check` 原来是直接往主窗口投 `WM_COMMAND`（假通过，
  正好绕过坏的那一段），现在用 `GetDlgItem` ＋ `BM_CLICK` 走真按钮；
  `--shot` 还会把日志框另存成同名 `.txt`，点没点得动直接读文本。
- 验证：`click.bmp.txt` 里出现 `== 三处一致性检查 ==` 与设备真实应答
  （`[X] 设备 192.168.1.64 读不到：设备登录被拒（HTTP 401, e=-23）`）。

### 1.1e（2026-11-05 14:05）同一套动作编译成 exe

- **为什么**：用户要求"做成一个 exe 软件，不要使用脚本"。脚本版在现场机器上要过
  ExecutionPolicy、PS 5.1/7 差异、UTF-8 BOM、中文编码四道关，exe 双击就跑。
- **是什么**：`运维箱通道配置.exe`（Win32 C，124 KB，静态链接）。界面、按钮、弹窗文案、
  「服务器 → 设备 → 本机」的失败即停顺序与 1.1 脚本版**逐条一致**；设备侧改用内置
  WinHTTP（不再靠 `Invoke-RestMethod`），服务器侧改用 `plink -m <临时脚本>`
  （不再把带引号和换行的脚本塞进命令行），本机侧只改 `remote.ini` 的 `token=` 一行。
- **没有变的**：三处判据、令牌字符集（1~63，`0-9A-Za-z-_ .~ / + @ =`）、
  `16000` 端口实测、以及"任何一步都改真实生效的文件/接口、没有预演"这条声明。
- **自检**：`运维箱通道配置.exe --shot 图.bmp check` 会把界面画出来截一张图、
  并自动点一次「一致性检查」；`--cli <动作> --log 文件.txt` 可无界面跑一遍（退出码 0/1）。
- 验证：设备真实应答 `HTTP 401 e=-23`（空口令）被正确回显；轮换在服务器不可达时停手、
  ini 的 md5 未变；导出的远端脚本 `bash -n` 通过。

### 1.1（2026-11-05 09:10）修「打开是空白界面」

- **现象**：1.0 打开后只有四个分组框的标题，里面一个控件都没有，看着像"软件没法用"。
- **原因**：子控件被 `Add` 到了**窗体**上，而分组框是先加的 —— WinForms 里后加的控件排在
  z 序**最底层**，于是标签/输入框/按钮全被分组框整块盖住（不是没创建，是被压住了）。
- **修法**：`New-Label/New-Text/New-Button` 都加 `$parent` 参数，子控件一律 `Add` 进各自的分组框，
  坐标改成相对分组框的客户区；输出框 `BringToFront()`。
- **顺手补的**：日志区开头印三条用法（先点哪个、之后点哪个、改完要重开 exe）。
- **自检开关**：`-Shot <图片路径>` 把界面画出来截一张就退出（用于确认"控件真的在界面上"，
  不进入交互）。以后改界面先用它出一张图看，别再靠肉眼想象。
- 验证：截图确认四个分组框内的标签/输入框/按钮全部可见、无裁切；`-NoGui -Action check` 仍全绿。
