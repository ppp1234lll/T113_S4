# 运维箱远程通道 · 新服务器（frps）部署手册

> 适用：给 ivsbox 运维箱新搭一台公网中转（frps），或把设备从一个服务器迁到另一个。
> 版本：2026-11-05　对应设备端 `frpc 0.68.0`、PC 端 `运维箱远程访问.exe 1.1.2`
> 相关：`远程通道使用说明.md`（原理）、`运维箱通道配置-操作声明.md`（PC 侧工具）
>
> **先说结论**：一台服务器只要装 **frps**（一个二进制 + 一个 toml + 一个 systemd 服务），
> 放通 **7000/TCP** 入站即可。服务器上**不需要**装 frpc、**不需要**开 8080/18081。

---

## 0. 开始之前（缺一条都会卡）

| 需要 | 怎么确认 |
|---|---|
| 一台有公网 IP 的 Linux（amd64/arm64 都行），root 可登 | `ssh root@新IP` 能进 |
| 公网 IP 固定（或已绑域名） | 云控制台看一眼 |
| **7000/TCP 入站放通**（安全组 + 本机防火墙） | 见第 4 步，两条都要 |
| 设备能上网（4G 或网线） | 设备 Web 首页看联网状态 |
| 知道设备 SN | 设备 Web 首页 / 机身标签（例：`0A19B4`） |

> frps 版本要和设备端 frpc 对上：**设备是 0.68.0，服务器就用 0.68.0**。
> 版本差太多会出现"能登录但没有 proxy"这类怪现象。

---

## 1. 装 frps（一条命令，整段粘贴）

在服务器上以 root 执行。脚本会：下二进制 → 写 `/etc/frp/frps.toml`（**自动生成 32 位令牌**）→
建 systemd 服务并启动 → 自检 → 把令牌打印出来。

```sh
FRP_VER=0.68.0
PORT=7000
DIR=/opt/frp
TGZ=frp_${FRP_VER}_linux_amd64.tar.gz

# 1) 下载（国内先走 gh-proxy，失败再走官方源）
command -v curl >/dev/null || { apt-get update -qq && apt-get install -y -qq curl; }
mkdir -p "$DIR" && cd /tmp
if ! curl -fsSL --max-time 300 -o frp.tgz "https://gh-proxy.com/https://github.com/fatedier/frp/releases/download/v${FRP_VER}/${TGZ}"; then
  curl -fsSL --max-time 300 -o frp.tgz "https://github.com/fatedier/frp/releases/download/v${FRP_VER}/${TGZ}"
fi
tar xzf frp.tgz && install -m 0755 "frp_${FRP_VER}_linux_amd64/frps" "$DIR/frps"
rm -rf frp.tgz "frp_${FRP_VER}_linux_amd64"

# 2) 生成令牌 + 写配置（令牌只在这里出现一次，记得抄走）
TOKEN=$(head -c 16 /dev/urandom | od -An -tx1 | tr -d ' \n')
mkdir -p /etc/frp
cat > /etc/frp/frps.toml <<EOF
bindAddr = "0.0.0.0"
bindPort = ${PORT}
auth.method = "token"
auth.token = "${TOKEN}"
webServer.addr = "127.0.0.1"
webServer.port = 7500
webServer.user = "admin"
webServer.password = "${TOKEN}"
log.level = "info"
log.maxDays = 7
EOF
chmod 600 /etc/frp/frps.toml

# 3) systemd
cat > /etc/systemd/system/frps.service <<EOF
[Unit]
Description=frp server (ivsbox tunnel)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=${DIR}/frps -c /etc/frp/frps.toml
Restart=always
RestartSec=3
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable --now frps
sleep 2

# 4) 自检
echo "---- 自检 ----"
"$DIR/frps" --version
systemctl is-active frps
ss -lntp | grep -E ":(7000|7500)[[:space:]]" || echo "!! 7000 没在听，看 journalctl -u frps -n 30"
curl -s --max-time 5 -u "admin:${TOKEN}" http://127.0.0.1:7500/api/serverinfo | head -c 200; echo
echo
echo "================ 抄走这三行 ================"
echo "服务器   $(curl -s --max-time 5 ifconfig.me || echo '<公网IP>')"
echo "端口     ${PORT}"
echo "令牌     ${TOKEN}"
echo "=========================================="
```

**为什么要这么配**：

| 配置项 | 值 | 为什么 |
|---|---|---|
| `bindPort` | 7000 | 设备与 PC 都连这个口；换口也行，但三处要跟着改 |
| `auth.method/token` | token | 设备、PC、服务器三处必须**同一串**，否则 frpc 报 `token in login doesn't match` |
| `webServer.addr` | `127.0.0.1` | 管理面板**只监听本机**，不对外暴露；要用就 SSH 隧道过去看 |
| `webServer.password` | 同一串令牌 | 现有约定复用令牌；面板账号 `admin` |
| `log.maxDays` | 7 | 日志别无限长 |

## 2. 放通 7000/TCP（**两条都要做**）

```sh
# 按机器上实际有的那个来（有三个就只挑一个）
ufw allow 7000/tcp                          # Ubuntu/Debian
firewall-cmd --add-port=7000/tcp --permanent && firewall-cmd --reload   # CentOS/RHEL
iptables -I INPUT -p tcp --dport 7000 -j ACCEPT                          # 裸 iptables
# 改完确认本机在听、且规则已生效
ss -lntp | grep 7000
```

**云安全组**（阿里云/腾讯云控制台）加一条入站规则：

| 协议 | 端口 | 源 |
|---|---|---|
| TCP | **7000** | `0.0.0.0/0`（板子走 4G，出口 IP 不固定，不能按 IP 限） |

> 不要照搬老方案里"还要开 18080/18081"的说法 —— 那是**设备主动发布 Web/摄像机代理**的旧架构，
> 现在设备只发布 ssh 一个代理，服务器侧不需要任何额外端口（见文末附录）。

**从外网验证**（在你自己的电脑上跑，不是服务器上）：
```powershell
Test-NetConnection 新IP -Port 7000     # TcpTestSucceeded : True
```

## 3. 设备侧：把设备指到新服务器

设备 Web（`http://设备IP`）→ 左侧 **「远程通道」**：

| 字段 | 填什么 |
|---|---|
| 服务器地址 | 新服务器公网 IP 或域名 |
| 端口 | `7000` |
| 令牌 | 上一步抄走的那串（32 位） |
| 有效期 | 长期（或按需小时数） |
| 开启通道 | 勾上 |

点 **「保存并生效」**。**不用重启设备**。

**成功标志**（三行，缺一行就是没通）：

```sh
# 设备上执行
tail -f /mnt/UDISK/log/frpc.log
```
```
[I] login to server success, get run id [xxxxxxxx]
[I] proxy added: [0A19B4]          ← 名字必须是这台设备的 SN
[I] [0A19B4] start proxy success
```

> **服务器地址改了要走 Web 页**（或 `config.apply` 改 `sys.tunnel.server.host`）。
> PC 侧的「运维箱通道配置」工具目前只管**令牌**和开关，不改设备地址 —— 地址在这页改。

## 4. PC 侧：让 exe 也连新服务器

两条路，任选：

**A. 用配置工具（推荐）**
1. 双击 `delivery-1.0.0/tools/运维箱通道配置/启动通道配置.cmd`
2. ① 服务器：填**新**地址 / 7000 / 新令牌
3. ③ 本机：确认 `remote.ini` 路径
4. 点 **「写入本机配置」** → 确认
5. 关掉并重开 `运维箱远程访问.exe`

> 工具的「一键轮换（三处同改）」适合**换令牌**；**换服务器地址**请在设备 Web 改地址，
> 工具这边只需要「写入本机配置」把新地址/令牌落到 `remote.ini`。

**B. 手工**：`运维箱远程访问.exe` →「服务器设置」→ 填新地址/端口/令牌 → 保存 → 重开。

`remote.ini` 长这样（在 `%LOCALAPPDATA%\ivsbox-remote\`）：
```ini
[server]
host=新IP
port=7000
token=新令牌
[device]
sn=0A19B4
```

## 5. 端到端验证（四道关，全过才算通）

| # | 在哪 | 命令 / 动作 | 期望 |
|---|---|---|---|
| 1 | 服务器 | `ss -lntp \| grep 7000` | `LISTEN`，进程 `frps` |
| 2 | 设备 | `tail -5 /mnt/UDISK/log/frpc.log` | `login to server success` + `proxy added: [SN]` + `start proxy success` |
| 3 | PC | 配置工具点「一致性检查」 | `通道实测：本机 16000 在监听（frpc 已登录成功）` |
| 4 | PC | exe 点「刷新」→ 双击某一路 | 列表出现设备真配的摄像机路数；隧道页 `code=200` |

第 3 关最省事：**本机 16000 在监听 = 这台 PC 已经用新令牌登录上新服务器了**。

## 6. 从旧服务器迁到新服务器（顺序很重要）

```
① 新服务器装好并自检通过（不碰老服务器，老的照常跑）
② 设备 Web 改：地址 → 新IP、端口、令牌（此时设备从老服务器掉线，PC 也连不上）
③ PC 侧：配置工具「写入本机配置」新地址+新令牌 → 重开 exe
④ 验证四道关
⑤ 老服务器观察 1~2 天没流量再停：systemctl disable --now frps
```

**为什么不能反过来**：设备一改地址就立刻从老服务器消失，PC 那边还指着老服务器，中间那几分钟是
"谁也连不上"。这个窗口不可避免，所以挑**不影响现场取图**的时间做。

**回滚**：设备 Web 把地址/令牌改回旧值 + PC 侧写回旧值，30 秒内恢复（老服务器只要没停就一直有效）。

## 7. 排错对照表

| 现象（frpc 日志原话） | 真实原因 | 处置 |
|---|---|---|
| `token in login doesn't match token from configuration` | 三处令牌不一致（服务器/设备/PC 有一处是旧值） | 对齐三处；用配置工具「下发令牌到设备」+「写入本机配置」 |
| `connect to server error: dial tcp ...: i/o timeout` | 7000 没放通（安全组或防火墙），或 IP 写错 | 外网 `Test-NetConnection` 复验 |
| `connection refused` | frps 没起 / 端口不是 7000 | `systemctl status frps`、`ss -lntp` |
| 登录成功但没有 `proxy added` | 该 SN 已在别处注册（同一 SN 两台设备抢） | 一台设备一个 SN，别复制配置 |
| `proxy added` 后无 `start proxy success` | 服务器版本与设备 frpc 差太多 | 服务器用 0.68.0 |
| 设备侧全绿，PC 侧 16000 不监听 | PC 连的是**另一台**服务器（`remote.ini` 没改/没重开 exe） | 看 exe 顶部 `服务器 x.x.x.x:7000` |
| PC 侧报 `no such api`（设备 Web 页） | 那是另一回事：设备 Web 二进制是旧件 | 见 `修改记录.md` 2026-11-05 08:09 条 |

服务器侧看日志：`journalctl -u frps -n 50 --no-pager`

## 8. 多台服务器 / 多台设备

- **一台 frps 可以带很多设备**，每台设备的 SN 就是它的 proxy 名字，互不干扰；令牌是**全服务器共用**的一串。
- **一台设备同一时刻只连一台服务器**（改地址就是迁移）。
- 想让不同客户/项目互不影响，就**各用一台 frps + 各自的令牌**；PC 侧在「服务器设置」里切换即可，
  但注意 `remote.ini` 只有一份，切过去要切回来。

## 附录：老方案里那些东西为什么不用了

老脚本（`_deploy/ecs_frps_setup.sh`）还会在服务器上装 **frpc + `/etc/frp/visitor.toml`**，
用 `SN-web`、`SN-camera:2` 两个 stcp 代理，把设备 Web 和摄像机映射到服务器的 18080/18081。
**现在不需要了**，原因：

1. 设备端现在只发布**一个**代理（`localPort = 22`，ssh），Web 与摄像机由 PC 侧通过 ssh 隧道自行转发；
2. 服务器上的 `visitor.toml` 里 `secretKey` 用的是 `md5(SN+令牌+svc)`（带 `-web`/`camera:2` 后缀），
   而设备端已改成 `md5(SN+令牌)` 前 16 位 —— **两边算法不同，照抄老脚本一定连不上**；
3. 少一个常驻进程（frpv）、少两个对外端口（18080/18081），攻击面也小。

所以本手册只装 `frps`。若你确实还要"服务器直接转发设备 Web"那套老能力，按老脚本做，
但 **secretKey 必须改成 `md5(SN+令牌)` 前 16 位**，不然握手永远失败（而且两边都不报"钥匙错"）。
