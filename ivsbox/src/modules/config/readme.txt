============================================================
src/modules/config  ——  配置管家：读取 / 校验 / 抗断电写盘 / 热更新
============================================================

【目录作用】
  在 `ivsboxd` 里当"配置管家"：从 `<dir>/ivsbox.json` 按点分键读出运行参数供各
  模块取值、能改回去存、改坏了不让服务崩、外部改了文件不重启就生效。
  属于模块层（编进 `libivmodules.a`），是**全工程唯一允许依赖 json-c 的地方**；
  对外头文件不暴露任何 json-c 类型。依赖 `libivcore`（iv_crc / iv_log / iv_ret）。
  各业务模块通过"按分类订阅通知"获取配置变化，不各自开一份句柄。

【文件说明】
  iv_config.c   配置模块全部实现（F1 读 / F2 取值 / F3 改存 / F4 补默认 /
                F5 原子写盘 / F6 inotify 热更新 / F7 分类事务通知）
  .gitkeep      目录占位

【实现状态】
  已实现（功能开发计划 M1-S8，含 §S8.1 口径落地）。

【约定与注意事项】
  - **非线程安全**：所有接口（含只读 get）只在 reactor 线程内调用，内部无锁。
  - **单文件口径**：全机只有一份 `ivsbox.json`，顶层为八个一级分类
    `sys/net/probe/camera/switch/elec/netthr/sensor`；同一份配置**只允许一个
    句柄**（第二次 open 同名返回 NULL）——各模块改用订阅通知（F7）。
  - **json-c 版本纪律**：只准用板端 sysroot（0.13.1）的 API 子集，成品动态依赖
    `libjson-c.so.4`；`libivcore`/`libivhal` 内不得出现 json-c 符号。
  - **零 malloc（本模块自身）**：句柄走静态池、条目定长数组；json-c 解析时库内部
    分配不受此约束。注意 `cfg_snapshot_t` / 渲染排序数组等栈占用各约 34 KB。
  - 返回码来自 `iv_ret.h`：键不存在 `IV_ENOENT`、类型不符 `IV_EPROTO`、
    校验失败 `iv_config_save()` 返回 `IV_EINVAL` 且**一个字段都不落盘**。
  - 业务键不得以 `_` 开头（该前缀保留给 `_meta` 元数据）。
  - 抗断电写盘顺序固定：写 `.tmp` → fsync 文件 → rename → fsync 目录。
  - `iv_config_watch_fd()` 返回的 inotify fd 由本模块持有并随 close 关闭，
    调用方只注册、不关闭。
  - 任何一次 `save()` 会按当前默认值表重渲染中文注释，手工加的注释会被覆盖
    （换来注释永不过期）。
