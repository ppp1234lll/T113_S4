============================================================
src/modules/recovery  ——  故障沿断电重启：正常(1)→故障(2) 单沿 → 0xD1 断电 5 s → 上电（已实现，M4-S4.4）
============================================================

【目录作用】
  把"网络状态从**正常(1)** 变 **故障(2)** 的单沿"翻成"采集板电源通道**断电 5 s
  再上电**"。属模块层（`libivmodules.a`）；动作经 `iv_report_send_cmd()` → `iv_link`
  下发 `0xD1`（继电器在采集板侧，与现网一致）。

  **只有这一条功能**：没有规则引擎、没有上游关联、没有熔断状态机、没有每小时/
  每天限频。架构 §7.6 原有那套"自愈策略引擎"（冷却/限频/上游关联/熔断四道保护）
  系由架构演绎而来，**现网没有**，已于 2026-10-13 作废并改写本步口径。

【约定与注意事项】
  - **触发（硬口径，逐字对齐参考项目 `det.c: det_main_network_and_camera_network()`）**：
    只有 `old == 1 && new == 2` 才动作。`0→2`（开机就是坏的 ⇒ 避免上电风暴）、
    `4→2` / `5→2`（延时/丢包 → 故障）、`1→4` / `1→5`（劣化）、`2→1`（恢复）
    **一律不触发**（延时/丢包不触发、恢复不触发）。
  - **动作映射**：主网（MN 两路**任一**）⇒ **继电器 1**（port 0）；**任一**摄像机
    （CNS 六路任一）⇒ **继电器 2~8 全部**（port 1~7，**整排重启、不定位单台**）。
    依据《智能箱通用功能统计.xlsx》"功能说明"第 13 条"网络故障后自动重启**所有**
    输出端口"。
  - **载荷**：`0xD1` ＋ JSON `{"port":<0~7>,"status":<0 关/1 开/2 重启>}`
    （架构 §18.2 冻结格式）。本模块只发 `status=0`（OFF）与 5 s 后的 `status=1`
    （ON）；`status=2`（采集板侧 15 s 断电）留给"系统操作"的人工单通道重启。
  - **关键机制：待发 FIFO**。一次摄像机故障要发 **7 条** `0xD1`，而 `iv_link` 的
    配对规则是"**同 cmd 在飞唯一**"（第二笔返回 `IV_EBUSY`）⇒ 连发 7 条只会有第 1
    条被接受。故模块自持 **16 槽 FIFO**，`iv_recovery_tick()` **每拍最多下发 1 条**：
    成功即出队；`IV_EBUSY` 保留队头、下一拍再试；其它负码丢弃该条并计数（不消费
    限次、不入断电相位）。ON 下发失败则**停在断电相位**等下一拍重试 —— 不能让
    继电器留在断电态。**这是串行化的全部机制，不需要"在飞完成回调"式耦合。**
    *代价（登记）*：`0xD1` 是控制命令（`iv_link` 只发一次、不重传），故"断电 5 s"
    是**近似值**＝"OFF 发出 ＋ 5 s ＋ 队内等待"；整排场景各通道错开约一拍（200 ms）。
  - **限次与冷却**：每通道独立状态机（相位 / 剩余次数 / 冷却截止）。动作后
    `netthr.reboot_interval_s`（默认 60 s，＝现网 `NETWAOK_RELOAD_TIME`）内不再
    动作；每通道最多 `netthr.reboot_max` 次；耗尽只告警不动作；**`reboot_max = 0`
    ⇒ 禁用自愈**（对齐现网出厂 `net_reload = 0`）。⚠ 出厂默认值现为 **3**（＝自愈
    默认开启），与现网出厂 0 不同 —— **登记为待用户决定项**。
  - **两处对参考实现有意不照抄（已登记）**：① 参考 `app_sys_net_relay_reload_num_times()`
    在冷却结束后会**自动重新武装**同通道（一次故障沿连做 N 轮，不管网络是否已恢复）
    ⇒ 本模块**只由新的故障沿驱动**；② 参考 `net_reload_num[]` **全程无复位点**
    （一轮用尽后该通道永久锁死到下次重启）⇒ 本模块按"剩余次数"语义，并给
    `iv_recovery_set_limits()` / `iv_recovery_reset()` 可复位。**另**：参考 `det.c`
    当前只对 `RELAY_2`/`RELAY_3` 动作（非整排），本步按**计划 ＋ 需求文档**做成整排。
  - **装配层注意**：`iv_report_send_cmd()` 传 `on_done = NULL` ⇒ `0xD1` 的**应答被
    静默丢弃**（控制命令的应答语义归应用层；`iv_status` 不消费 `0xF1`/`0xD1`/`0xD2`
    应答的既有口径不变）。**装配层不得另持第二份 `iv_link`**，否则"同 cmd 在飞唯一"
    会被绕过。
  - **未做（如实登记，不得当成已完成）**：① **主网（MN 两路任一）故障 ⇒ 继电器 1
    这条动作未接线** —— 主网五态**没有模块级出口**（`iv_netmgr` 只暴露
    `iv_netmgr_active_wan()`；`iv_report_env_t.mn[]` 至今无生产者），而直接用
    `iv_probe_state()` 会**绕开 netmgr 的迟滞判据**（`nm_fail_n`/`nm_ok_n`），
    单次探测超时就会切主网电 ⇒ 未擅自接，建议先加"带迟滞的主网可用性出口"
    （**卡用户拍板**）。② 板端实测：拔摄像机网线 → 继电器动作 → 平台上报/日志核对
    （M4 退出条件）。③ `control.db` 落盘（表结构待 S9）。④ 需求文档"输出路数可配置"
    未做键。
