============================================================
src/modules/report  ——  上报装配层（S3.6）
============================================================

【目录作用】
  把 M2 的采集板链路与 M3 的队列/传输拼成**端到端可运行的一层**，补齐 S2.4 交出的
  "上报/查询响应的业务数据生成（装配层职责）"。它自己不实现协议、不实现传输，
  只负责"把谁接到谁、什么时候发什么"：

    采集板 ── ttySAC5 ──► iv_serial ──► iv_link ──► iv_status（状态镜像）
                                                         │
                        (周期/触发) ──► build_seg ──► iv_queue_push（落盘）
                                                         │
    平台 ◄── TCP ── iv_transport ◄── pump.pull/ack ───────┘
         └─ on_rx ──► iv_proto_recv ──► route ──► 查询应答（## + JSON）──► on_tx
         └─ 心跳/ACK ◄── iv_proto(ack/heartbeat) ──► on_tx ──► iv_transport_send

【文件说明】
  iv_report.c           上报装配层实现（生命周期、串口薄包装、采集板/平台回调、
                        查询处理、组段、驱动、Reactor 回调）

【关键口径（详见 include/ivsbox/iv_report.h 文件头）】
  - 发送路由分两条：周期/立即上报**入队**（断线积压、恢复补传）；查询应答/ACK/心跳
    **直发**（非 UP 时传输层返回 IV_ESTATE，不积压过期帧）。
  - 数据段字段顺序/取值口径以架构 **§18.1**（平台帧与上行数据段，2026-10-10 冻结）
    ＋ 参考实现 `General_Version/main/APP/User/src/com.c` 为准。
  - **`DS` 原值直传、不做映射**（平台侧语义未定义，不猜）；`DEVTYPE` 用字段表口径。

【约定与注意事项】
  - 只经各模块公共头 ＋ 回调交互，不碰任何模块的私有数据。
  - 单写者：全部接口只在装配层（Reactor）单线程内调用，内部无锁、零 malloc
    （`iv_report_t` 由调用方持有，约 15 KB）。
  - 时间一律由调用方以 `now_ms` 传入；`r == NULL` 时由调用方按节拍自己调 `step()`。
  - 本层只注册**串口 fd 的 READ 事件 ＋ 一个节拍定时器**，不注册传输层 fd；
    收发节拍由 `IV_REPORT_TICK_MS`（200 ms）驱动，代价是补传吞吐 ≈ 5 件/s（登记遗留）。
