## 3. 重设计原则

1. **运维台定位**：深色侧栏 + 浅色内容区的专业后台风格（类主流云控制台），保证长时间表单操作不疲劳，状态一目了然。
2. **一眼看到结论**：每页顶部先给"结论区"（大数字指标卡 / 状态徽标），细节往后排。
3. **状态一律徽标化**：`● 正常 / ● 故障 / ● 延时` 彩色 pill（点 + 底色 + 字），禁止只靠文字颜色。
4. **数字等宽**：所有数值 `font-variant-numeric: tabular-nums`，IP/MAC/OID 用等宽字体。
5. **改皮不改骨**：页面 id、导航结构、API 调用、交互时序、关键文案全部保持现状（详见 §6）。

### 4.2 形状与组件

- 圆角：卡片 12px、控件（输入/按钮）8px、徽标 999px；卡片描边 1px `--line` + 轻阴影。
- 侧栏 224px：顶部 logo 30px + 「IVSBox / 运维终端」双行；导航项高 40px、图标 17px、选中态主色左条 3px + 半透明主色底 + 白字；底部版本 / 账号 + 改密 / 退出按钮。
- 页头（topbar）64px 吸顶：页名 18px + 一句副标题；右侧**链路状态徽标 + 自动刷新开关（5s）+ 更新时间**。
- 指标卡（metric）：12px 灰标签 + 26px/700 大数 + 13px 单位 + 可选脚注；结论型状态放脚注徽标。
- 状态徽标（pill）：高 22px、色点 6px、12px 字；四种语义色 + dim 灰。
- 表格：外包圆角 10px 容器；表头 `#f7f9fc` 12px 间距；行悬停 `#f7faff`。
- 表单：label 12px 次色在上、控件高 36px；分组框圆角 10px、组标题带 3px 主色竖条、**右上角淡灰等宽字显示配置键前缀**（如 `net.server.*`，替代裸键名问题）；每个分类/卡片收尾一个**吸底操作条**：脏值计数（橙）+ 项数/版本 + 重新载入 + 保存修改。
- 确认弹窗：自绘模态（遮罩 + 居中卡 + 取消/确认），替代原生 `confirm()`；正文必须保留现有 confirm 里的协议信息（见 §6.3）。
- 空态：圆形浅底大图标 + 标题 + 一句说明 + 徽标（如 `规划：M6`）。
- 登录页：全屏深蓝渐变（160°，`#0b1830→#0f2748→#123a6b`）+ 网格纹理 + 两张光晕；居中 860px 分栏卡——左 55% 品牌区（深蓝渐变底：logo 46px、产品名、一句定位文案、4 条特性点、底部型号/版本/改密提示），右侧表单区（账号/密码/登录 + 底部提示行）。
- 图标：Lucide v0.462.0（ISC 许可，可商用），源文件已在仓库 `web_ui_images/icons/`（10 个导航图标），原型已内联同款 path。

## 5. 逐页设计说明（现状 → 设计稿）

> 每节先列对应图片，再给布局要点。图片为 1440×900 视口截图。

### 5.1 登录（现状 01 → 设计稿 01）
- 左品牌 + 右表单分栏卡；品牌区给产品定位与四条能力点，填补"这是哪台设备、能干什么"的语境。
- 表单区保留：账号、密码、登录按钮；新增底部提示行（锁定/找回口令指引，文案可按实际策略调整）。
- 强制改密卡（出厂默认口令）沿用同款卡片风格，密码规则原文（多行 `<pre>`）样式化为浅灰规则块。

### 5.2 总览（现状 02 → 设计稿 02）
- 顶部 4 张指标卡：软件版本（脚注=硬件型号）、运行时长（脚注=开机时刻）、系统时间（脚注=校时来源）、设备 SN（**默认值时数值橙色 + 脚注橙徽标「出厂默认值 · 未做工厂写入」**）。
- 左卡「设备身份」：两列描述列表（型号/芯片/身份 MAC/网口 MAC/主机名/内核）。
- 右卡「写入设备身份」：三条警示缩成一行 ⚠ 提示；两个输入框 + 写入按钮收在操作条。

### 5.3 网络（现状 03 → 设计稿 03）
- 顶部 4 张状态卡：网络状态 / 活动出口 / 主网1 / 主网2，脚注放语义徽标（链路判定带迟滞、探测目标）。
- eth0 / usb0 各一张网口卡（状态徽标 + IP/掩码/MAC 描述列表），替代原先 7 个碎 KV 块。
- 「网络参数」表单卡：分组框（本机网络 `net.*`、平台服务器 `net.server.*`），组标题右上角淡键前缀；吸底操作条显示脏值与版本。

### 5.4 定位（现状 04 → 设计稿 04）
- 左卡「定位结果」：未定位/已定位结论徽标 + 数据时延徽标；**经纬度 24px 等宽大数**为视觉主体；海拔/速度/航向/UTC 描述列表。
- 右卡「信号与链路」：卫星数 / HDOP / 时延三小格（时延超限变橙/红）+ 串口与累计字节。
- 底部「链路与解析统计」单行表：解析成功、校验错/结构错、超长/噪声、校时成功/被拒；副标题保留排障口诀（收不到字节=线/波特率；有字节不定位=天线/遮蔽）。

### 5.5 控制板（现状 05 → 设计稿 05）
- 顶部 4 张大数指标：电压 / 电流 / 温度 / 湿度。
- 「三路继电器」：每路一张通道卡（路号 + port 号、状态徽标、四项读数、吸合/断开按钮），替代表格里挤按钮；口径说明保留在副标题。
- 「运行参数」（0xE1 键名对照）与「通信链路」（协议计数）左右并排描述列表。
- 「告警阈值」只读表格，副标题注明"修改请到运维页"，消除与可配置项的混淆。

### 5.6 摄像机（现状 06 → 设计稿 06）
- 「六路实时状态」：6 张小卡（路号 + 状态徽标 + 配置里的 IP），故障红 / 延时橙 / 正常绿。
- 「检测与账号配置」：检测方式组、SNMP 组、通道组（每路一面板：厂商/IP/MAC/用户/口令(密文)/录像开关/码流/拉流地址）；操作条吸底。

### 5.7 设备档案（现状 07 → 设计稿 07）
- 卡片头：标题 + 数量徽标 + 右侧主色「重新搜索摄像机」按钮。
- 表格：品牌列做 `info` 徽标、发现方式列做 `dim` 徽标，其余等宽字体；空态用 §4.2 空态组件（icon=archive）。

### 5.8 交换机（现状 08 → 设计稿 08）
- 参数表单（基础信息 / SNMP 采集两组）+ **OID 槽位表格化**（槽位/含义/OID 三列），替代 5 列裸键名输入框阵列；OID 值仍可编辑（表格内输入框）。
- 「SNMP 采集结果」：状态徽标 + 最近采集时间 + 两个采集按钮紧贴结果表。

### 5.9 媒体（现状 09 → 设计稿 09）
- 空态设计：圆形图标位 + 「媒体功能尚未启用」+ 说明 + `规划：M6` 徽标。M6 上线后此区改为媒体网格。

### 5.10 配置（现状 10 → 设计稿 10）
- 顶部 8 个**分类胶囊 tab**（sys 基础参数 / net 本机网络 / … / sensor 传感器），一次只看一类，终结 194 键平铺。
- 类内仍按分组框渲染，组标题右上角键前缀；操作条显示"该类 N 项 / 全部 194 项 · 版本"。
- 「出厂默认值对照」表格保留在下方（键/类型/默认值）。

### 5.11 运维（现状 11 → 设计稿 11）
- 顶部三张**操作卡**：同步本机时间 / 搜索摄像机（普通卡 + 次级按钮）、**重启设备（红描边浅红底卡 + danger 按钮）**，每卡一句用途说明——危险操作从配置流里隔离出来（P10）。
- 「检测与自愈」（netthr.* / probe.*）与「电阈值与传感器」（elec.* / sensor.*）两组表单卡 + 吸底操作条。

## 6. 工程落地约束（实现者必读）

重设计**只改呈现层**；以下与后端协议、现场习惯绑定的行为是现状代码刻意为之，重做时**必须原样保留**（出处均为 `ivsbox/web/static/app.js` 现行注释）：

1. **页面与导航**：10 个页面 id（overview/net/gps/board/camera/devices/switch/media/config/maint）与 PAGES 结构不变；切页收定时器的行为不变。
2. **口令口径**：`PASS_HINT` 密码规则提示与服务端 `IV_WEB_PASS_HINT_TEXT` 是同一句话，必须整块保留（含换行）；强制改密流（登录返回 `must_change` / 任意接口 403 `must change password` 时全局切改密卡）逻辑不变。
3. **继电器控制**：下发 0xD1 后按钮冷却 2.2s 回读一次、5s 再回读一次并解锁（采集板镜像滞后一拍，只回读一次会出现"点了没生效"）；失败提示"同命令在飞"分支保留。改用模态确认时，确认正文需保留 `0xD1 port N status=0/1` 协议信息。
4. **null ≠ 0 ≠ 空串**：后端取不到的值是 JSON null，显示"—"；GPS 坐标只在 `valid` 为真时显示；`sn_source === 'default'` 时 SN 用告警样式（设计稿中的橙徽标）。
5. **配置表单**：中文标签来源是 `GET /api/config?defaults=1` 的 `d` 字段（与配置文件注释同源），不得前端另抄对照表；`title` 悬停显示完整键名的行为保留（可升级为组标题键前缀 + 悬停兜底）；脏值跟踪（`.dirty` 高亮）、版本号提交、`e === -3` 版本冲突提示保留。
6. **只读与可写分离**：网络页「当前生效」取自内核（`/api/overview` 的 `d.net.link`），与配置项留空语义（"不在此指定"）不能混。
7. **自动刷新**：GPS / 控制板页现有 5s 定时刷新保留；新增的页头"自动刷新"开关与"更新于"时间戳是纯前端增强，不改变轮询实现。
8. **资源引用**：图标用 `web_ui_images/icons/`（ISC 许可头部注释勿删）；logo/favicon 用 `web_ui_images/brand/`；登录背景可用 `web_ui_images/login/` 或按原型内联渐变实现。
9. **兼容目标**：设备端浏览器以 Chrome/Edge 现代版为主；无需支持 IE；静态资源总体积增量控制在 100KB 内（当前 style.css 约 6KB，重写后预计 15~25KB，无构建链，保持原生 CSS/JS，不引入框架）。
